## 1. 世界观

主角在原本的世界里一直打工，最后猝死了。

死后他发现自己家在阴间有一间工厂——美美当资本家。

要当资本家就得有人替他干活，所以他雇了一个假小子秘书鬼当左膀右臂，同时兼任新人引导。

---

## 2. 游戏概述

### 2.1 一句话

**像 Minecraft 红石那样工程化搭建的 2D 自动化游戏，只不过所有元件都是鬼。** 鬼能是唯一资源：鬼被规则触发时产出鬼能，鬼能收进守财鬼的仓储，再用仓储里的鬼能盖下一只鬼。

### 2.2 与现有自动化游戏的差异

市面上的自动化游戏（《沙金工业》《异星工厂》）里，机器是主角、能量是消耗品，配方解锁就是全部成长。

本作的差异：

- **鬼是规则，不是机器。** 每只鬼只有一条最基本的行为规则。
- **没有采料，没有配方解锁，没有加工链。** 只有一种能量——鬼能。
- **工程化搭建是第一乐趣。** 玩家拼的是布局与连接，不是解锁树。
- **信号与 CD 是鬼自带的。** 玩家不需要像 MC 早期那样手搓时钟与延时电路；触发节奏内置在鬼里。
- **升级的唯一形式是扩建。** 没有数值成长，只有「我造出了一个更复杂的东西」。

### 2.3 目标体验

- 前 30 秒：看懂「摆鬼 → 连鬼 → 它自己动」
- 前 2 分钟：发现「产鬼能的鬼」和「收鬼能的鬼」连起来能自己滚起来
- 一整局：不断在「造引擎」和「造产线」之间分配有限的空间

## 3. 核心玩法

### 3.1 玩法循环

```
摆鬼 → 连鬼 → 鬼自动运转
              ↓
      被规则触发的鬼产出鬼能（掉在地上）
              ↓
      点一下鬼能 → 收进守财鬼的仓储
              ↓
      用仓储里的鬼能盖下一只鬼
              ↓
      限时内累计产出达标 → 结算星级 → 解锁新鬼
```

### 3.2 玩家操作

| 操作 | 输入 | 说明 |
|---|---|---|
| 放置鬼 | 从底部鬼牌栏拖到地图 | 拖动放置，消耗仓储里的鬼能 |
| 连线 | 从鬼的输出端口拖到输入端口 | 〔初〕点源端口 → 点目标端口，系统自动生成 L 形路径 |
| 手动触发 | 点击该鬼 | 吊死鬼：点一下自己拉一次（无长舌鬼反拉时用） |
| 拾取鬼能 | 点击地上的鬼能 | 收进最近的守财鬼仓储 |
| 拆除 | 点击鬼或线段 | 释放占格 |
| 移动鬼 | 拖动 | 仅暂停时可拖，运行中不可 |

### 3.3 胜负条件

- **目标**：限时内**累计产出**鬼能达到 `goal_spirit`
- **失败**：倒计时归零且未达标，可重试，不扣任何东西
- **结算**：三轴评分（效率 / 手动 / 空间）→ 1~3 星 → 解锁新鬼

「累计产出」与「仓储存量」是两个独立计数，见 §4.6。

## 4. 鬼能经济（唯一资源）

### 4.1 只有一种能量

**鬼能是全局唯一的资源与货币。** 没有原料、没有中间形态、没有配方、没有垃圾、没有供品交付。

因此以下概念从本作中**全部移除**：

| 移除项 | 原因 |
|---|---|
| 采料区 / 采集鬼（贪食鬼、细嚼鬼） | 没有原料可采，鬼能直接由鬼产出 |
| 形态 Form / 配方 Recipe / 加工鬼（灶鬼） | 只有一种能量，没有可加工的形态 |
| 供品口 / 交付线 / 目标交付 | 计分改为累计产出鬼能 |
| 垃圾 / 收容鬼 | 无损耗来源 |
| 产能区（作为独立建筑） | 产能不是区域，产能是一只鬼的行为 |

**鬼能只有一条循环：产出 → 存储 → 消费 → 扩大产出。**

### 4.2 鬼能怎么产出

鬼能**不由区域定时刷新，只由规则触发产生**。

| 触发方式 | 说明 |
|---|---|
| 动作触发（主） | 鬼完成一次有效动作 → 产出若干鬼能，掉在它旁边 |
| 条件触发 | 鬼的状态满足条件（如「被推动」「收到触发」）→ 产出鬼能 |

产出规则写在每只鬼自己的行为里，不写在关卡里，不写在全局表里。

### 4.3 守财鬼 = 仓储区

**守财鬼本身就是仓储区。** 它是一只鬼，不是一个建筑子系统。

| 项 | 规则 |
|---|---|
| 造价 | **0 鬼能**（唯一免费的建筑） |
| 占位 | 2×1 |
| 功能 | 存放鬼能；玩家花鬼能建造时，从守财鬼的存量里扣 |
| 数量 | 可建多只，仓储不互通（各自独立存量），便于分区管理 |
| 初始 | 每关预置一只守财鬼，保证玩家开局就有仓储可用 |

**建仓储不花鬼能，但仓库里的鬼能能花。** 守财鬼造价 0 是刻意的：它保证玩家任何时刻都能把手里的鬼能存起来，不会因为「钱不够建仓」而卡死循环。

### 4.4 两种收集方式

| 方式 | 操作 | 归属 |
|---|---|---|
| 手动 | 玩家点击地上的鬼能 | 收进最近的守财鬼 |
| 自动 | 拾穗鬼把相邻格鬼能吸入守财鬼 | 收进指定守财鬼 |

手动拾取是**核心操作之一**，不是凑合：早期关卡只给手动，让玩家亲手建立「产出 → 存储 → 消费」的因果感；后期给拾穗鬼，玩家的乐趣从「不停点点点」变成「把自动化补全」。

### 4.5 建造消耗与开局赠送

| 项 | 来源 |
|---|---|
| 造鬼、造线 | 守财鬼仓储里的鬼能 |
| 造守财鬼 | 不消耗（造价 0） |
| 开局赠送 | 每关开局赠送一份初始鬼能 |

**每关开局必须赠送初始鬼能。** 关卡数据里的 `start_spirit` 是硬性字段，没有它关卡无法通过（编辑器校验）。赠送量以「够玩家盖出第一个完整产线且有余量」为准，参考值见 §14。

### 4.6 两个计数器

| 计数器 | 含义 | 用途 |
|---|---|---|
| **仓储存量** | 当前各守财鬼里的鬼能 | 建造消耗 |
| **累计产出** | 本关产出的鬼能总量 | 关卡目标与结算 |

产出时鬼能从「累计产出」记一次账，同时以实体形态掉在地上等被拾取。**掉了没捡的鬼能不计入仓储，但已经计入累计产出**——捡晚了不影响过关，只影响你还能不能继续盖鬼，这正好构成「效率 vs 手动」的取舍。

## 5. 红石对照：MC 元件 → 鬼

本作的元件库直接对标 Minecraft 红石。鬼 = 红石元件的「有性格版本」。

### 5.1 对照表

| MC 元件 | 鬼 | 相同点 | 本作差异 |
|---|---|---|---|
| 红石粉 | 线鬼 | 有方向、可拐弯、分段传东西 | 传的是鬼能 |
| 活塞 | 长舌鬼 | 周期性推 / 拉前方目标 | 舌头是活的，会自己抓 |
| 中继器 | 吊死鬼 | 单向、延时、隔离信号 | **延时 CD 内置**，不需要玩家额外搭延时电路 |
| 拉杆 | 吊死鬼（手动态） | 玩家手动拨动一下 | 点击即拉一次，松开即回 |
| 比较器 | 判官鬼 | 比较两路信号强弱 | 比较的是鬼能数量 |
| 侦测器 | 感应鬼 | 检测某个格子的状态 | 检测格内是否有鬼 / 有多少鬼能 |
| 箱子 | 守财鬼 | 存放物品 | 存放鬼能，造价 0 |
| 漏斗 | 拾穗鬼 | 自动把东西吸走 | 把相邻鬼能吸入守财鬼 |
| 时钟 / 活塞阵列 | 永动机（涌现） | 玩家自造 | **本作内置**：长舌鬼 + 吊死鬼 就是永动机 |

### 5.2 唯一的规则差异

MC 里「红石块 + 中继器 + 比较器 = 永动机」需要一个会动的东西当钟摆，通常得靠活塞阵列硬搓出来。

**本作省掉这一步：触发节奏内置在鬼身上。**

- 每只鬼自带 `cd`（动作周期），自己按自己的节奏动
- 信号沿连线传播，触发即触发，不存在「信号断了导致时序错乱」
- 因此玩家第一关就能直接搭出稳定循环，不需要先学「搓时钟」

一句话：**MC 的红石玩法原样保留，但把最烦的那部分（时钟与延时电路）直接内置。**

### 5.3 元件库是「最基本的东西」

所有鬼的行为规则都必须能一句话说完，且只描述「我自己做什么」：

- 长舌鬼：**我会拉。**
- 吊死鬼：**我会伸。**
- 不倒翁鬼：**我被推动时会掉鬼能。**
- 守财鬼：**我存鬼能。**
- 拾穗鬼：**我把旁边的鬼能吸走。**
- 判官鬼：**我比两边的鬼能谁多。**
- 感应鬼：**我报告这一格有没有鬼。**

两只鬼凑一起会发生什么，**不在任何一只鬼的规则里**，由物理层涌现（§6）。

## 6. 物理层：共振的涌现

### 6.1 核心认知：没有「共鸣规则」这回事

**共鸣不是一条需要被写下来的规则，而是物理层自动叠加后的自然结果。**

参考 Minecraft 的红石电路：红石块的逻辑只有「有电 / 没电」，中继器只有「充能 / 断电」，比较器只有「比较两个信号」——**没有任何一条规则写着「红石块 + 中继器 + 比较器 = 一个永动机」**。但你把这三个方块按正确的位置摆好，它就是个永动机。规则没变，涌现变了。

鬼工厂同理：

| 你以为的写法 | 实际该有的写法 |
|---|---|
| 长舌鬼 + 吊死鬼 = 永动机 | 长舌鬼会自动拉取，吊死鬼会自动伸展，两者相邻且连上时，行为自然叠加 |
| 长舌鬼 + 不倒翁鬼 = 产线 | 不倒翁鬼的规则只有「我被移动 → 我掉鬼能」，谁来推都一样 |
| 两根线接一起 = 一条线 | 线只管传，谁接谁都一样 |

**推论：鬼的行为只描述「我自己做什么」，不描述「我和谁在一起会怎样」。** 后者是玩家的发现，不是程序员的分支。

所以本节不设「共鸣规则表」。取而代之的是三样东西：

1. **鬼的自主行为** —— 每只鬼自己就会做的事（长舌鬼自己会拉取，吊死鬼自己会伸展）
2. **端口标签** —— 只用来检验「能不能联动」，不决定「联动出什么」
3. **物理求解** —— 每 tick 统一结算所有鬼的意图与冲突

### 6.2 端口标签的唯一职责：合法性检查

端口标签（`ACTION` / `RECEPTACLE`）**只回答一个问题：这两个鬼之间允许建立物理连接吗？**

```
长舌鬼.ACTION = GRAB      （长舌鬼能作用于「被抓住的东西」）
吊死鬼.RECEPTACLE = GRAB  （吊死鬼能被抓住）
→ 标签命中，允许连接
```

标签**不回答**「连上以后会发生什么」。那是物理层自己算出来的。

已用标签：`GRAB` 攫取 / `HANG` 悬挂 / `PICKUP` 拾取 / `STORE` 存放 / `COMPARE` 比较 / `SENSE` 感知。

| 标签 | 谁发布 | 谁接受 | 物理含义 |
|---|---|---|---|
| `GRAB` | 长舌鬼 | 吊死鬼 | 舌头抓取力可以作用在吊绳上 |
| `HANG` | 吊死鬼 | 长舌鬼 | 吊绳可以挂住舌头 |
| `PICKUP` | 拾穗鬼 | 地面鬼能 | 地面上的鬼能被吸入 |
| `STORE` | 守财鬼 | 拾穗鬼 / 玩家点击 | 鬼能可以入库 |
| `COMPARE` | 判官鬼 | 判官鬼 | 比较两路鬼能数量 |
| `SENSE` | 感应鬼 | 判官鬼 | 读取格内状态 |

**校验时机**：玩家连线时立刻检查并给出反馈（线变红＝标签不匹配）。连上之后标签就不再参与了。

### 6.3 物理层：意图与结算

每只鬼每 tick 产生一个**意图**（Intent），描述「我想做什么」。所有意图收集完毕后统一结算，解决冲突。

意图类型：

| 意图 | 产生者 | 含义 |
|---|---|---|
| `PULL` | 长舌鬼 | 抓住相邻格的目标，拉向自己 |
| `EXTEND` | 吊死鬼 | 向目标方向伸展一格 |
| `RETRACT` | 吊死鬼 | 收回伸展 |
| `PUSH` | 长舌鬼（缩回时） | 把抓住的目标推出去 |
| `SWAY` | 不倒翁鬼 | 被推动时的回摆反应 |
| `PRODUCE` | 不倒翁鬼 | 产出鬼能 |
| `COLLECT` | 拾穗鬼 | 从相邻格取走鬼能 |
| `STORE` | 守财鬼 | 把鬼能计入存量 |
| `TRANSFER` | 任意 | 沿连线送一份鬼能 |

结算规则（每 tick，一次性跑完）：

1. **收集意图**：所有鬼同时提出意图，互不知情
2. **合法性过滤**：意图涉及的连接若标签不匹配，该意图作废
3. **冲突消解**：同一目标被多只鬼争抢时，按下列优先级裁决
   - 优先级 = 鬼的 `priority` 字段，高者胜
   - 同优先级则按格子距离近者胜，再相同则按放置顺序（先放的胜）
4. **执行**：胜出的意图执行，其余作废
5. **连锁**：执行产生的新状态可能触发下一 tick 的意图

**关键：第 3 步的优先级裁决是唯一的「仲裁规则」。** 所有「两只鬼相邻会怎样」的答案，都从这里长出来，不需要额外写规则。

### 6.4 涌现案例：三个玩家自己会发现的机关

#### 案例一 · 永动机（长舌鬼 + 吊死鬼）

```
长舌鬼        吊死鬼
[本体][舌头]——[吊绳]
   ↓ 自动拉取     ↓ 自动伸展
```

- 长舌鬼的舌头自动伸出，试图抓住相邻格的目标（`GRAB`）
- 吊死鬼的 `RECEPTACLE = GRAB`，所以它可以被抓住
- 吊死鬼挂上后自动伸展，伸展方向顶住长舌鬼的舌头
- 长舌鬼缩回时把吊死鬼拉近，吊死鬼伸展时又把长舌鬼顶远
- **两者来回推拉，永不停歇**

代码里**没有任何一行写着「长舌鬼 + 吊死鬼 = 永动机」**。只有：长舌鬼每 2.0s 尝试 PULL、吊死鬼每周期尝试 EXTEND，以及标签校验允许它们建立连接。

**如果玩家不想用长舌鬼反拉**——吊死鬼也支持手动：点一下它，它自己拉一次。这是早期关卡里玩家第一次能主动推动局面的操作。

#### 案例二 · 产线（长舌鬼 + 吊死鬼 + 不倒翁鬼）

```
长舌鬼 → 吊死鬼 → 不倒翁鬼 → 不倒翁鬼
（拉）    （中继）   （产鬼能）  （产鬼能）
```

长舌鬼拉吊死鬼，吊死鬼的伸展又推不倒翁鬼，不倒翁鬼的规则是「我被移动 → 我掉鬼能」。

**链长不是参数，是玩家摆出来的几何结果。** 能接多长取决于摆了多少只、占位接不接得上、空间预算还剩多少。

#### 案例三 · 鬼能竞争（两只不倒翁鬼）

两只不倒翁鬼如果被同一段推力链交替推动，产鬼能时机就错开了——玩家因此学会调整链条长度与间距，把推力节奏错开以提高产出。**这一段没有任何特判，是各自 CD 与推动顺序自然错开的结果。**

### 6.5 鬼的类别（描述性标签）

按工程流程，鬼分四类：**运输 / 产出 / 存储 / 感知**。

**类别是描述性标签，不参与任何判定逻辑。** 它只用于两件事：给玩家读懂这只鬼是干什么的；给关卡设计选教学点。

| 类别 | 默认行为 | 典型鬼 |
|---|---|---|
| 运输 | 把鬼能从一处送到另一处 | 线鬼、拾穗鬼 |
| 产出 | 凭空或被推动时产出鬼能 | 不倒翁鬼 |
| 存储 | 存鬼能 | 守财鬼 |
| 感知 | 读取周围状态并输出 | 判官鬼、感应鬼 |

**分类不参与任何判定逻辑。** 两只运输鬼连上不会触发「运输加成」。

`GhostData.category` 字段存这个分类，值域：`transport` / `produce` / `store` / `sense`。

### 6.6 代价

代价不是「共鸣的附加惩罚」，而是**物理约束的必然结果**——空间、材料、时间不够时，机关就是转不动。

| 代价 | 物理来源 |
|---|---|
| 空间占用 | 推力链与仓储抢同一份空间预算 |
| 背压 | 缓冲与线的容量有限，满了就停 |
| 手动疲劳 | 手动拾取是有限的注意力资源 |
| 优先级劣势 | 同目标争抢时优先级低的鬼空转 |
| 反弹 | 鬼被推挤时会推挤别人（案例一） |

## 7. 推挤链（产能的物理形态）

### 7.1 链的结构

长舌鬼的舌头推挤链上的鬼，推力沿链连锁传递。

```
长舌鬼 ──推──▶ 吊死鬼 ──推──▶ 不倒翁鬼 ──推──▶ 不倒翁鬼
              (中继)        (产鬼能)          (产鬼能)
```

- 舌头伸出 → 推前方一格 → 缩回时把抓住的鬼拖回一格
- 推拽免费，不需要任何物料
- 吊死鬼自动荡回（`HANG` 端口自作用），玩家只负责第一次挂绳

**这条链不是一条被写下的规则**，而是三只鬼各自的自主行为叠加的结果——详见 §6.4 案例二。

### 7.2 产出公式

```
一次循环产出 = 链上不倒翁鬼数 × 单只产量
产出速率     = 链上不倒翁鬼数 ÷ 舌头 CD
```

数值见 `Docs/Ghosts.md` §3。

### 7.3 链的长度

**链长不是一个独立参数，而是机关功能嵌套出来的结果。** 能嵌套多长取决于：玩家摆了多少只鬼、占位能不能接得上、空间预算还剩多少。

链能接多长就多长，接不上就断。**没有链长上限参数**，链的上限就是玩家摆得出来的长度。

### 7.4 取舍

| 想更多鬼能 | 代价 |
|---|---|
| 链上多塞不倒翁鬼 | 多占格子，挤掉仓储空间 |
| 缩短舌头 CD | 速率更高但节奏更密 |
| 加吊死鬼当传力者 | 多占 1 格，链条才能继续往后延 |

## 8. 物流系统

### 8.1 线

线也是鬼，有方向、有容量。

| 项 | 规则 |
|---|---|
| 走向 | 正交折线，不斜 |
| 方向 | 输出端口 → 输入端口，不可反向 |
| 容量 | 每段有限，见 §14 |
| 移动 | 离散格步进，不用插值 |

不用连续插值是因为整个游戏是「一次一次像机关」的节奏，插值与网格对不齐。

### 8.2 缓冲与背压

每只鬼有输入缓冲与输出缓冲，容量按鬼不同。

背压连锁（自动发生，不需要玩家干预）：

```
输出缓冲满 → 停止收上游 → 输入缓冲满 → 停止从上线取货
→ 线满 → 上游鬼输出缓冲满 → 继续往上游传 → 鬼能堆积在地上没人捡
```

玩家应对：重排布局、减少上游供给、或加拾穗鬼自动收。

### 8.3 地面鬼能

掉落物是**真实实体**，占据格子，数值上**无上限**。

视觉上限只是表现层的堆叠压缩：同格最多画 5 个图标，超出转 `×N` 角标，底层数值完全准确。

玩家必须能看出哪里堵了：

| 信号 | 表现 |
|---|---|
| 缓冲满 | 鬼身脉冲警示 |
| 线满 | 线段上鬼能变红闪烁 |
| 地面堆积 | 堆叠高度上升 |

## 9. 地图与空间

### 9.1 地图

地图是预先设计好的固定小网格，含地形与障碍。玩家在既定地图里布置鬼和线，不能改变地形。尺寸逐关设计时定。

### 9.2 空间预算

| 项 | 规则 |
|---|---|
| 鬼 | 按其几何占位形状占据的格子数 |
| 线 | 每经过 1 格占 1 格，拐角格只算一次 |

线的占位是空间管理的核心：一条绕远的线吃掉 6 格，就少放 6 只鬼。

### 9.3 只有一条经济线，但取舍仍在

**鬼能既是产出也是耗材**，所以玩家永远在问同一个问题：**这 20 鬼能，是盖第 3 只不倒翁鬼，还是盖第 2 个守财鬼？**

| 选择 | 得到 | 失去 |
|---|---|---|
| 多盖产能鬼 | 产出速率上升 | 仓储不够，产出的鬼能堆在地上浪费 |
| 多盖守财鬼 | 仓储容量上升、能继续盖鬼 | 产能不变，且守财鬼本身不产鬼能 |
| 多盖线 | 鬼能流动更顺 | 线占格，且要花钱 |
| 全手动拾取 | 零建造支出 | 注意力被占住，来不及扩容 |

一条经济线不代表没有决策——**决策点从「两条线怎么分配」变成了「同样的钱买效率还是买容量」。** 这在 MC 里就是熟悉的「红石预算」体验。

## 10. 关卡

### 10.1 难度设计

难度按概念递增，不按数值递增。

| 章 | 新增概念 |
|---|---|
| 1 | 放置、连线、产出鬼能、手动拾取、建造消耗 |
| 2 | 仓储与扩建、推挤链、空间取舍 |
| 3 | 自动拾取（拾穗鬼）、感知（感应鬼 / 判官鬼） |
| 4 | 多目标、严限时、窄地形 |

### 10.2 Demo 三关

| 关 | 时长 | 教什么 | 引入 | 初始鬼能 |
|---|---|---|---|---|
| 1 | 90s | 产出 → 手动拾取 → 建造；长舌鬼 + 吊死鬼的永动机 | 长舌鬼、吊死鬼、不倒翁鬼、守财鬼 | 30 |
| 2 | 120s | 仓储扩建与推挤链；手动点不过来时怎么办 | 守财鬼（第二个）、长舌鬼（第二个） | 40 |
| 3 | 120s | 自动拾取与感知；补全自动化 | 拾穗鬼、感应鬼、判官鬼 | 50 |

每关开局赠送初始鬼能（`start_spirit`），确保玩家不需要先白手起家就能开始搭建。

### 10.3 评分

| 轴 | 含义 | 引导 |
|---|---|---|
| 效率 | 单位时间累计产出 | 造线紧凑、CD 叠得好 |
| 手动 | 所需点击次数 | 优化组合而非硬点 |
| 空间 | 占用格数 / 可用格数 | 做取舍而非铺满 |

1★ 达标 / 2★ 基准时间 / 3★ 三轴同时达标。

### 10.4 关卡数据结构

```
Data/Levels/Level01.tres
  start_spirit: 30              # 开局赠送鬼能（必填）
  goal_spirit: 60               # 累计产出目标
  time_limit: 90
  space_budget: 12
  obstacles: [...]
  terminals: [{position: (9,5), accepts: Storage}]   # 预置守财鬼
  available_ghosts: [LongTongue, Hanged, Tumbler, WealthKeeper]
```

新增关卡 = 加一个 .tres，零代码改动。

### 10.5 元进度

局外层是解锁表，每关通过后自动解锁下一项。无货币、无攒点。

| 解锁项 | 作用 | 何时 |
|---|---|---|
| 新鬼 | 可放置的新规则单元 | 主体 |
| 新机制 | 如槽位可解锁、线可升级 | 后期 |

关卡必须声明可用鬼池白名单，防止解锁的鬼带来超纲规则。

不做局外货币——它会引入「这局多刷点」的元游戏，与产线专注度冲突。

## 11. 教程

### 11.1 形式

秘书鬼的对话框 + 聚光灯遮罩（周围变黑，中间标亮目标）。

- `CanvasLayer` + 全屏半透明黑 `ColorRect` + 挖亮区（Shader 或 `Light2D`）
- 亮区跟随目标世界坐标实时更新
- 流程：点继续 → 亮区移到下一目标 → 完成操作 → 对话框继续
- 内容与关卡数据绑定，不硬编码在 UI 脚本里
- 教程期间游戏暂停

### 11.2 教学范围

只教五件事：拖放、连线、点手动鬼、拾取鬼能、花鬼能建造。

〔初〕第 1 关结尾留一个 5 秒的互动信号（位移反射闪一下 + 鬼能 +3 + 一句秘书鬼的吐槽），让玩家第一次看到两只鬼互动。

### 11.3 秘书鬼

- 定位：主角的秘书兼左膀右臂，新人引导者
- 性格：假小子，嘴硬爱吐槽，但干活利落
- 台词方向：毒舌不刻薄，讲效率讲规矩，不卖萌
- 功能：教程发言人，兼后期的剧情提示

## 15. 技术实现

### 15.1 目录

```
Code/
├── Autoloads/
│   ├── SaveManager.gd      # 存档读写
│   ├── SignalBus.gd        # 资源/关卡/板面信号
│   ├── ExportSettings.gd   # 全部数值
│   └── Util.gd             # 复用音频与定时器
├── Common/
│   ├── GhostTag.gd         # 端口标签常量与配对校验
│   ├── GhostData.gd        # 鬼数据结构（类别、占位、端口、优先级）
│   ├── LevelData.gd        # 关卡数据结构
│   ├── GridUtil.gd         # 网格坐标、邻接、几何占位计算
│   ├── UIPalette.gd        # UI 12 色板
│   ├── UIEffects.gd        # UI 动效库
│   └── ResourceUtil.gd     # 资源属性读取
└── Entities/
    ├── Board/      # 网格、鬼组件、线鬼、运行时与交互
    ├── Level/      # 关卡流程、目标、计时、结算
    ├── Tutorial/   # 新手教程与聚光灯
    ├── Setting/    # 设置面板
    ├── LevelSelect/# 关卡选择
    └── StartMenu/  # 主菜单

Data/
├── Ghosts/  Levels/  Tutorial/   （全部 .tres）
```

**新增一只鬼 = 一个 .tres + 一个行为方法，不改核心逻辑。** 核心层没有「鬼 A 和鬼 B」这种分支，只有「意图 → 统一结算」。

### 15.2 信号

新增到 SignalBus：

```
GhostPlaced / GhostRemoved / GhostDisplaced
GhostActionDone / SpiritChanged / StorageChanged / ResourceChanged
LevelStarted / LevelCompleted / LevelFailed / GhostUnlocked
TutorialStepChanged / SaveGameWritten
SpiritProduced / SpiritPicked / LineCreated
```

**没有 `ResonanceTriggered`。** 因为共鸣不是一次触发，而是一个持续状态——鬼一直连着就一直生效。

### 15.3 运行循环

逻辑与渲染分离，逻辑固定 20 Hz。**每 tick 是一次「收集意图 → 统一结算」，不是「逐只鬼跑 if 分支」**：

```
1. 提出意图    每只鬼按自己的 CD 与状态提出本 tick 的意图
               （长舌鬼 PULL、吊死鬼 EXTEND、不倒翁鬼 SWAY、
                 拾穗鬼 COLLECT、守财鬼 STORE…）
2. 合法性过滤  意图涉及的连接若端口标签不匹配，该意图作废
3. 冲突消解    同一目标被多只鬼争抢时按 priority → 距离 → 放置顺序裁决
4. 执行        胜出的意图执行，其余作废
5. 产出落地    PRODUCE 意图在鬼身边生成地面鬼能实体，计入累计产出
6. 物流推进    鬼能沿连线步进一格，背压自上游向下游传播
7. UI 刷新     资源条、仓储存量、警示、倒计时
```

**关键：第 1 步里没有「如果 A 和 B 相邻就怎样」的分支。** 每只鬼只产出自己的意图，谁赢由第 3 步统一裁决。所有「两只鬼凑一起会怎样」都是这三步叠出来的结果，见 §6。

暂停条件：打开设置 / 教程对话框显示 / 规划模式（按住快捷键临时暂停并自由移动鬼）。暂停保留全部状态。

### 15.4 规范

遵循 `src/AGENTS.md`：

- 公共方法 PascalCase + `##` 文档注释，内部方法 `_snake_case`
- 跨实体通信一律走 SignalBus，不直接调用别的方法
- 数值全部导出到 `ExportSettings.gd`
- `class_name` 只在 `Common/` 声明
