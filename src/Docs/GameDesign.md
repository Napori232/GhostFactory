## 1. 世界观

主角在原本的世界里一直打工，最后猝死了。

死后他发现自己家在阴间有一间工厂——美美当资本家。

要当资本家就得有人替他干活，所以他雇了一个假小子秘书鬼当左膀右臂，同时兼任新人引导。


---

## 2. 游戏概述

### 2.1 一句话

**在一间格子化的阴间工厂里摆出会自己干活的鬼，把鬼能变成贡品——限时、限地、限量交付。**

---

## 3. 核心玩法

### 3.1 玩法循环

```
放置鬼（花鬼能） → 接端口 → 运行
        ↓
生产鬼按周期产出鬼能，掉在旁边随机空格
        ↓
采集鬼在框选范围内一格一格搜过去，拾起掉落物
        ↓
送仓库（= 建造货币） 或 送处理鬼（= 贡品原料）
        ↓
处理鬼加工成贡品，损耗出杂质；杂质占格，要再处理
        ↓
贡品送进贡品口 → 限时内交够数 → 结算
```

### 3.2 玩家操作

| 操作 | 输入 | 说明 |
|---|---|---|
| 放置鬼 | 从底部鬼牌栏拖到地图，可以改变方向 | 消耗仓库里的鬼能；刚体放下即固定 |
| 调整采集范围 | 拖拽采集鬼的边角手柄 | 框一个矩形，决定它的搜索区域 |
| 接线 | 从输出端口拖到输入端口 | 有向；自动生成正交折线路径；空间不够则拒绝 |
| 切换状态 | 点击鬼本体 | 待机 / 运行 / 暂停 三态循环切换 |
| 拆除 | 点击鬼 | 释放占格，全额退还鬼能 |
| 拖动鬼 | 拖拽 | 仅**未运行**时可拖；刚体与柔体都可拖，运行中一律不可拖 |
| 复制 | 选择一部分鬼 | 释放自动复制 |
| 手动拾取 | 点击资源拖拽 | 收进仓库 |

### 3.3 胜负条件

- **目标**：限时内把 **N 个贡品**送进贡品口
- **失败**：倒计时归零且未达标；可重试，不扣任何东西（关卡内不存档）
- **结算**：三轴评分（效率 / 手动 / 空间）→ 1~3 星 → 解锁新鬼

## 4. 系统一：鬼

### 4.1 定义与三条描述轴

**鬼就是一台台机器。** 每只鬼独立占格，有输入输出端口，有自己的行为。

一只鬼由三条轴描述，三条轴互相独立：

| 轴 | 取值 | 作用 |
|---|---|---|
| **鬼的种类** | 生产 / 采集 / 运输 / 处理 | 决定它干什么活 |
| **触发类型** | 自动 / 被动 / 检验后 | 决定它什么时候动 |
| **可动性** | 刚体 / 柔体 | 决定它能不能被推、能不能被拖动 |

三条轴的组合产生具体行为。**描述轴不是判定开关**：同类鬼相接不会触发「同类加成」，发生什么由物理层算出来（§8）。

### 4.2 鬼的种类

| 类型 | 干什么 | 有输入吗 | 有输出吗 | 典型形态 |
|---|---|---|---|---|
| **生产鬼** | 按周期凭空产出鬼能，掉在自身旁边的随机空格 | 无 | 无（产出直接落地） | 鬼能 |
| **采集鬼** | 在框选范围内一格一格搜，把掉落物拾进输出缓冲 | 无（拾取对象来自地面） | 有 | 鬼能 / 杂质 |
| **运输鬼** | 沿已连的路径把一件东西搬到下一台机器 | 有 | 有 | 原样搬运 |
| **处理鬼** | 把输入的东西加工成贡品，按损耗产出杂质 | 有 | 有 | 鬼能 → 贡品；杂质 → 回收鬼能 |

**端口数量允许为 0。** 生产鬼没有输入端口（它不消耗任何东西），采集鬼的输入对象是地面掉落物而非管道里的东西。端口的方向语义不变：有输入端、有输出端。

**生产鬼只产鬼能。** 「用产出的鬼能再造一只生产鬼」是玩家的行为，不是生产鬼的第二种产出。

### 4.3 触发类型

| 类型        | 何时动          | 含义                   |
| --------- | ------------ | -------------------- |
| **自动触发**  | 按自己的周期动      | 机器自带节奏与 CD，不变        |
| **被动触发**  | 被别的鬼影响时才动    | 被推动、被挡住、被撞击后才有反应     |
| **检验后触发** | 检验物理层的变化后才继续 | 产出先落到待检状态，检验合格才生效或计分 |

**检验后触发是通用机制**，给特定鬼设置即可：任何一只鬼都可以被标为检验后触发，含义统一为「它做出来的东西要先过检验才算数」。

**检验由关卡设施执行**（贡品口），检验对象是送到的物品：合格 → 计分；不合格 → 转为杂质。杂质因此有了合法来源——它是「不合格但没消失的产物」，不污染关卡目标，却会占格。

### 4.4 可动性与拖拽

| 属性 | 定义 | 后果 |
|---|---|---|
| **刚体** | 放下之后不可动 | 推不动、挤不走；位置永久固定 |
| **柔体** | 放下之后可动 | 会被推动链带动、会互相挤开；自身行为也可以包含位移 |

**拖拽规则：柔体可拖动，刚体不可拖动。** 拖动只在鬼**未运行时**开放（放置阶段与暂停阶段），运行中一律锁定，防止玩家手动改写产线布局。

柔体的「可动」指的是**被物理推动**，不是玩家拖动。柔体被推离原设计位就是布局失误的代价，玩家只能通过暂停重排来纠正。

**放置前可自由预览占位**，拆除全额退还鬼能——试错成本要低，玩家才敢摆复杂产线。

### 4.5 状态机

| 状态 | 含义 | 玩家可切换 |
|---|---|---|
| **待机** | 放好但没开工 | ✓ |
| **运行** | 正在干活 | ✓ |
| **暂停** | 临时按住，停工但保状态 | ✓ |
| **故障** | 因条件不满足而停摆 | ✗（由条件触发） |

**待机 / 运行 / 暂停 点击循环切换**：待机 → 运行 → 暂停 → 待机。

**故障的进入条件**（任一满足）：

- 输出缓冲满且无下游可去（下游缓冲也满）
- 处理鬼缺料且等待超时
- 采集鬼的搜索区被完全堵死
- 掉落的鬼能无处可落（生产鬼四邻无空格且自身缓冲满）

**故障由玩家手动点击恢复**：点击该鬼 → 回到待机。自动恢复会让玩家失去「我在修机器」的存在感，因此不做自动恢复。

**状态与在制品**：切到待机或暂停时，加工中的半成品保留在输入缓冲里，不消失、不返还。

### 4.6 参数

| 参数 | 含义 | 单位 |
|---|---|---|
| **速度** | 移动一格所需时间 | 秒 / 格（越小越快） |
| **处理时间** | 完成一次作业所需时间 | 秒 / 次 |
| **输入容量** | 输入缓冲能存几件 | 件 |
| **输出容量** | 输出缓冲能存几件 | 件 |

参数的适用随类型变化：

| 类型 | 速度 | 处理时间 | 输入容量 | 输出容量 |
|---|---|---|---|---|
| 生产鬼 | — | 生产周期 | — | ✓ |
| 采集鬼 | 搜索步进 | 拾取耗时 | — | ✓ |
| 运输鬼 | ✓ | — | ✓ | ✓ |
| 处理鬼 | — | ✓ | ✓ | ✓ |

**生产鬼的生产周期就是它的处理时间**，不再单开参数。**运行时零消耗**：鬼工作时不耗鬼能，只有建造花鬼能。运行耗料留待后续再考虑。

### 4.7 端口

每只鬼有输入端口与输出端口，可以有多个，**数量允许为 0**。端口是接入点，不是触发开关。

- 玩家从输出端口拉到输入端口，自动生成正交折线路径
- 路径每经过一格占一格，拐角格只算一次
- 空间不够则拒绝接线并给出提示
- 端口不兼容（例如产线物料与目标形态对不上）在放下瞬间就拒绝，不静默失败

**接线的是「通路」，不是「规则」。** 接上之后鬼能怎么流、机器之间怎么互相影响，由物理层与各鬼自身行为算出。

## 5. 系统二：世界与空间

### 5.1 格子

世界是方格的。每一格有明确归属：空地、鬼占位、掉落物、杂质、障碍。

- 鬼按**几何形状**占位（直线、L 形、T 形、多格不规则），**形状由关卡设计与鬼的种类决定，占格总数是形状的结果**
- 掉落物与杂质各占 1 格；同格可堆叠，视觉上最多画 5 个图标，超出转 `×N`，底层数值准确
- 掉落物占格不可通行，柔体鬼不能穿过掉落物

### 5.2 有限空间

每一关的空间有限，需要合理运用。空间预算有三种消耗方：

| 消耗方 | 说明 |
|---|---|
| 鬼占位 | 几何形状的面积 |
| 线路 | 每经过一格占一格 |
| **掉落物与杂质** | 掉在地上就是占格，不捡走就一直占着 |

**地面占用是本作最狠的约束之一**：生产鬼一直在掉东西，处理鬼一直在掉杂质。地面堵了，采集鬼就搜不到路，鬼就进故障。

Demo 三关的空间预算：18 / 22 / 26 格。

### 5.3 掉落规则

生产鬼每完成一次生产，在**自身四邻的空格中随机一格**掉落 1 单位鬼能。

- **四邻均匀**：四个方向等概率，看哪里有空位置就掉哪
- 四邻无空格 → 产出进入自己的输出缓冲
- 缓冲满 → 故障
- 掉落位置随机 → 采集鬼必须真的去找，这正是「搜索区大小」成为决策的原因

**摆放生产鬼的位置就是在设计掉落分布**：让生产鬼贴着搜索区边缘放，掉落大多落在区内。

## 6. 系统三：鬼能经济

### 6.1 一份鬼能，两个去处

鬼能既是**建造货币**也是**加工原料**，而且是同一种东西。这是本作经济设计的核心张力。

| 去处 | 路径 | 意义 |
|---|---|---|
| **仓库** | 采集鬼输出 → 仓库口 | 转成建造本钱，扩大产能 |
| **贡品** | 采集鬼输出 → 处理鬼 → 贡品口 | 转成关卡目标，交付贡品 |

**同一堆掉落物只能走一条路。** 拿去建鬼就少一份贡品，反之亦然。玩家的每一个决定都是「我要钱还是要命」。

不把鬼能拆成两种资源，而是让**同一实体有两个去向**，取舍由玩家做，不靠数值平衡。

**仓库口与贡品口是关卡预置设施**（不是鬼），玩家不能移动也不能拆除。

**仓库是调控杠杆**：它是建造货币的蓄水池，容量上限与接收速率由关卡数据指定。仓库**进多去少** → 仓库很快满 → 顶住上游生产 → 玩家被迫把一部分掉落物分流去加工。难度与关卡节奏都靠这个旋钮调。

### 6.2 形态与配方

形态是全局词表，关卡引用；转换只能由配方决定。

| 形态 | 来源 | 去向 |
|---|---|---|
| **鬼能** | 生产鬼掉落 | 仓库 / 处理鬼 |
| **贡品** | 处理鬼加工产出 | 贡品口（检验后计分） |
| **杂质** | 处理鬼损耗产出 | 地面占格；可被采集鬼拾起，再送处理鬼做**再处理** |

**再处理不会再生杂质**：处理鬼处理杂质时**全额回收鬼能**，且不再掉杂质。这是让系统收敛、也让再处理值得占用机器位的关键一条。

**关卡目标只有单一形态**（贡品）。多形态目标留到后续章节。

### 6.3 损耗

处理鬼加工不是无损的：

- 每加工 4 件产出 1 件杂质（损耗率 25%）
- 杂质不污染关卡目标，但它占格
- 不清理杂质，地面会被慢慢吃满

**清理杂质的成本是玩家自己的时间或机器位数**——没有免费的垃圾处理。

### 6.4 生产与货币

- 建造消耗仓库里的鬼能；拆除**全额退还**，鼓励试错重排
- 每关开局赠送初始鬼能，保证玩家开局能摆出第一条链
- 运行时零消耗

## 7. 系统四：收集

### 7.1 搜索

采集鬼的搜索范围是玩家框选的一块**矩形区域**。

- 采集鬼**一格一格地搜**，路径由深度优先（DFS）求解：先沿一条方向走到尽头，再逐条回退换方向
- 搜索区越大，需要遍历的格子越多，找到掉落物的平均耗时越长
- 搜索区越小 → 搜得快，但可能覆盖不到随机落点

### 7.2 范围博弈

掉落位置随机，搜索成本随面积增长。玩家因此面对三个同时成立的取舍：

| 想 | 代价 |
|---|---|
| 搜索区小 → 搜得快 | 覆盖不全，落点在区外就永远找不到 |
| 搜索区大 → 覆盖全 | 每找一件都要多走很多格，吞吐下降 |
| 多个采集鬼分头搜 | 占用更多格子与更贵的机器 |

**摆放生产鬼的位置本身就是在设计掉落分布**：让生产鬼贴着搜索区边缘放，掉落大多落在区内。

**搜索区面积不限上限**，范围大小由算法开销与空间预算自然约束：搜索区越大，遍历越慢、占格越多，收益递减由玩家自己判断。关卡可以用推荐值引导（例如教学关推荐 3×3），但玩家可以自己框更大的。

### 7.3 拾取

采集鬼走到掉落物所在格 → 拾取（〔初〕0.5 秒 / 件）→ 进入输出缓冲 → 沿连线送出。

- 输出缓冲满 → 停止拾取（背压）
- 搜索区内没有任何掉落物 → 空跑，持续消耗时间

## 8. 系统五：物理驱动层

### 8.1 原则

**鬼的行为只描述「我自己做什么」，不描述「我和谁在一起会怎样」。** 两台鬼凑一起发生什么，是物理层叠加的结果，不是写下来的规则。


因此本文**不设规则表**。规则表是白名单：没写到的组合就不发生任何事，玩家的组合大半无效。

### 8.2 位移的结算单位

物理是连续的，格子是离散的。**本作以格为位移的最小结算单位**：所有推动、挤压、行走的结果都以「一格」为单位落地，动画负责把这格铺得顺。

**物理与算法的分工**：物理决定**谁动了谁、谁挡路**；DFS 决定采集鬼的**搜索顺序与步数**；格子决定**动到哪里停下**。这样「物理驱动」与「一格一格查找」不再互斥。

### 8.3 推动链

被动触发的柔体被推一下 → 撞到前方的柔体 → 推力沿链传递。

- 链上每被推动一次，就发生一次该鬼自己的反应（产出、掉落、加工）
- 刚体在链上是**止点**：推力到刚体为止，刚体不动
- 链长不是参数，是玩家摆出来的几何结果；接不上就断

### 8.4 代价

代价不是额外贴上去的惩罚，是约束的自然结果：

| 代价 | 来源 |
|---|---|
| 空间不足 | 机器、线、掉落物、杂质抢同一份格子 |
| 背压 | 缓冲与线路容量有限，满了就停 |
| 损耗 | 加工必然掉杂质 |
| 随机 | 掉落位置随机，找不到就空跑 |
| 碰撞 | 柔体会被挤开，被挤到就偏离原设计位 |

## 9. 关卡

### 9.1 难度设计

按概念递增，不按数值递增。每关只加一个新维度。

| 章 | 新增概念 |
|---|---|
| 1 | 放置、运行状态、掉落、手动拾取、建造消耗 |
| 2 | 采集鬼与搜索区范围、连线输送 |
| 3 | 处理鬼、加工、杂质占格、仓库 vs 贡品的分配 |

### 9.2 Demo 三关

| 关 | 时限 | 目标 | 空间 | 教什么 | 引入鬼 |
|---|---|---|---|---|---|
| 1 | 90 s | 12 个贡品 | 18 格 | 放置、运行、掉落、手动拾取、建造 | 生产鬼、仓库口、贡品口 |
| 2 | 120 s | 18 个贡品 | 22 格 | 采集范围、连线输送、背压 | 采集鬼、运输鬼 |
| 3 | 120 s | 20 个贡品 + 不超 3 个杂质残留 | 26 格 | 加工损耗、杂质清理、产能与交付抢空间 | 处理鬼 |

### 9.3 评分

| 轴 | 含义 | 引导 |
|---|---|---|
| 效率 | 单位时间交付贡品数 | 缩小搜索区、缩短线路 |
| 手动 | 所需点击次数 | 用采集鬼替代手捡 |
| 空间 | 占用格数 / 预算 | 做出取舍而不是铺满 |

1★ 达标 / 2★ 基准时间 / 3★ 三轴同时达标。

### 9.4 关卡数据结构

```
Data/Levels/Level01.tres
  start_spirit: 30              # 开局赠送鬼能
  goal_offer: 12                # 目标贡品数
  offer_form: Offer             # 目标形态（单一）
  time_limit: 90
  space_budget: 18
  storage_capacity: 20          # 仓库容量上限
  storage_in_rate: 2            # 仓库接收速率（件/秒）
  obstacles: [...]
  facilities: [{type: Storage, position: (2,2)}, {type: Offer, position: (9,5)}]
  available_ghosts: [Producer, Collector, Transporter, Processor]
```

新增关卡 = 加一个 .tres，零代码改动。

### 9.5 元进度

局外层是解锁表，每关通过后自动解锁新鬼与新机制，无货币、无攒点。关卡必须声明可用鬼白名单，防止解锁的鬼带来超纲规则。

## 10. 教程

### 10.1 形式

秘书鬼的对话框 + 聚光灯遮罩（周围变黑，中间标亮目标）。

- `CanvasLayer` + 全屏半透明黑 `ColorRect` + 挖亮区（Shader 或 `Light2D`）
- 亮区跟随目标世界坐标实时更新
- 流程：点继续 → 亮区移到下一目标 → 完成操作 → 对话框继续
- 教程期间游戏暂停

### 10.2 教学范围

只教五件事：放置、切换运行、拾取掉落物、建造消耗、连线。

第 1 关结尾留一个 5 秒的互动信号（推动演示 + 掉落 + 秘书鬼一句吐槽），让玩家第一次看到两只鬼互动。

### 10.3 秘书鬼

- 定位：主角的秘书兼左膀右臂，新人引导者
- 性格：假小子，嘴硬爱吐槽，但干活利落
- 台词方向：毒舌不刻薄，讲效率讲规矩，不卖萌

## 14. 技术实现

### 14.1 目录

```
Code/
├── Autoloads/
│   ├── SaveManager.gd      # 存档读写
│   ├── SignalBus.gd        # 资源/关卡/板面信号
│   ├── ExportSettings.gd   # 全部数值
│   └── Util.gd             # 复用音频与定时器
├── Common/
│   ├── GhostTag.gd         # 端口标签词表与连线合法性校验
│   ├── GhostData.gd        # 鬼数据结构（类型/触发/可动性/占位/端口/参数）
│   ├── FormData.gd         # 形态数据（鬼能 / 贡品 / 杂质）
│   ├── RecipeData.gd       # 配方数据
│   ├── LevelData.gd        # 关卡数据结构
│   ├── GridUtil.gd         # 网格坐标、邻接、几何占位计算
│   ├── UIPalette.gd / UIEffects.gd / ResourceUtil.gd
└── Entities/
    ├── Board/      # 网格、鬼组件、掉落物、线路、运行时与交互
    ├── Level/      # 关卡流程、目标、计时、结算
    ├── Tutorial/   # 新手教程与聚光灯
    ├── Setting/    # 设置面板
    ├── LevelSelect/# 关卡选择
    └── StartMenu/  # 主菜单

Data/
├── Ghosts/  Forms/  Recipes/  Levels/   （全部 .tres）
```

**新增一只鬼 = 一个 .tres + 一个行为方法，不改核心逻辑。** 核心层没有「鬼 A 和鬼 B」这种分支。

### 14.2 现状

- `Code/Autoloads/`（SignalBus / Util / ExportSettings / GlobalValue / SaveManager）与 `Code/Common/`（FormData / RecipeData / GhostTag / GridUtil 等）可复用
- **玩法层（Board / Level / Tutorial）当前处于删除状态**，按本策划案重做
- `Data/Forms/` 与 `Data/Recipes/` 已按鬼能 / 贡品 / 杂质重写完毕

### 14.3 信号

SignalBus 上现有的：

```
GhostPlaced / GhostRemoved / GhostDisplaced
GhostStateChanged / GhostFaulted
SpiritProduced / SpiritDropped / SpiritPicked
ItemDelivered / OfferScored / ImpurityCreated
LineCreated / LineBlocked
LevelStarted / LevelCompleted / LevelFailed / GhostUnlocked
TutorialStepChanged / TutorialCompleted / SaveGameWritten
```

**没有 `ResonanceTriggered`。** 涌现效果不是一次触发，是持续状态。

### 14.4 运行循环

逻辑与渲染分离，逻辑固定 20 Hz。每 tick 是一次「收集意图 → 统一结算」：

```
1. 状态推进    待机/运行/暂停/故障的迁移与超时判定
2. 意图收集    每只鬼按自己的周期提出意图（生产/拾取/搬运/加工/推动）
3. 合法性过滤  端口标签不匹配的意图作废
4. 冲突消解    同一目标被多只争抢 → priority → 距离 → 放置顺序
5. 执行        胜出的意图执行，其余作废
6. 位移结算    以格为单位落地推动与移动
7. 掉落与产出  生成地面掉落物、杂质、贡品
8. 物流推进    物品沿连线步进，背压向上游传播
9. UI 刷新     资源条、缓冲、故障警示、倒计时
```

暂停条件：打开设置 / 教程对话框显示 / 规划模式。暂停保留全部状态。

### 14.5 规范

遵循 `src/AGENTS.md`：

- 公共方法 PascalCase + `##` 文档注释，内部方法 `_snake_case`
- 跨实体通信一律走 SignalBus
- 数值全部导出到 `ExportSettings.gd`
- `class_name` 只在 `Common/` 声明
