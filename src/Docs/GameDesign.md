# 鬼工厂 — 策划案

> 状态：核心玩法与系统设计已定，进入实现准备。美术与音乐风格暂缺，后续补写。
> 技术栈：Godot 4.7.2，仓库 `src/` 为 Godot 工程根，`res://` = `src/`。
> 本文档为项目设计事实来源，与 `src/AGENTS.md` 的代码规范配套使用。
> 标记约定：**〔定〕** 已确定 · **〔初〕** 初版参数待调 · **〔待〕** 待拍板
> 本版重点：补齐系统层（物流、建造、运行循环、经济闭环），修掉前后矛盾。

---

## 1. 定位

> **每个鬼不是一台机器，而是一条规则。**
> 玩家用鬼的规则搭一条会自己运转的产线；两只鬼互相满足对方的规则时发生「共鸣」，共鸣才是鬼能的主要来源。

与同类产品的差异：

| 参照物 | 它做什么 | 本作差异 |
|---|---|---|
| 《沙金工业》(Satisfactory) | 物流吞吐与资源分流，机器是主角 | 鬼是规则而非机器；能量来自规则互喂而非机器耗电 |
| 《末日电涌》(Rogue Voltage) | 模块互相连线成环，模块互触发电 | 同样的循环链，但主题是鬼，且共鸣带代价 |
| 《工厂》(Factory Fun) | 连线本身给奖励 | 只在连线的瞬间给一次性奖励，没有持续运转 |
| Opus Magnum | 机械臂互顶、压力传递 | 同样讲互作用，但它是解谜式单解，不是产线吞吐 |
| Minecraft 活塞 | 推挤方块、循环往复 | 本作把活塞逻辑移植为「鬼的舌头」，作为位移产能的物理基础 |

**核心结论**：两个规则单元互为能源、以拓扑方式组合，这个层次市面上是空的。这是本作的卖点。

---

## 2. 设计目标与红线

**要证明的核心乐趣**：把两只鬼贴在一起会「来电」，而且这个电足以让玩家做出有代价的选择。

**红线**（踩了就毁掉核心）：

1. **鬼之间必须有取舍，不能只有增益。** 每种共鸣至少附带一项代价（空间占用、产出打折、产生垃圾、寿命限制、占位、反向效果）。
2. **共鸣必须靠空间拓扑产生，不靠数值堆叠。** 加鬼要重新排布，不是加一层。
3. **手动操作是节拍器，不是主要产能来源。** 手动鬼占产量瓶颈，但不占产能主体，否则退化成手速游戏。
4. **不做纯数值科技树。** 元进度只解锁新鬼，新鬼带来的是新规则，不是 +10%。
5. **玩家只能调整布局。** 运行中的鬼不可被玩家拖动，位移只由机制产生（防位移产能被主动刷）。
6. **两条经济线必须解耦。** 鬼能（造引擎用）与交付（过关用）不能由同一个系统产出，否则玩家只能造一种东西。

## 3. 系统总览

### 3.1 层级结构

```
┌─ 约束层 ────────────────────────────────────────┐
│  空间预算 │ 舌头 CD │ 关卡时间 │ 目标值          │  ← 玩家被限制的东西
└──────────────────────────────────────────────────┘
        ↓ 约束决定玩家能摆出什么
┌─ 产出层 ────────────────────────────────────────┐
│  产能区（自持）        交付链（物流）              │
│  长舌→吊死→不倒翁×N   采集→加工→供品口           │
│  产 鬼 能             产 供 品（计分）            │
└──────────────────────────────────────────────────┘
        ↓ 两条线分别消耗
┌─ 物流层 ────────────────────────────────────────┐
│  线（容量/方向）│ 缓冲（格数）│ 背压（阻塞）      │
└──────────────────────────────────────────────────┘
        ↓ 物料来源
┌─ 输入层 ────────────────────────────────────────┐
│  采集区（形状自由 + 面积参数比）│ 掉落物 │ 垃圾  │
└──────────────────────────────────────────────────┘

横切：共鸣系统（端口 + 反射）—— 判定「谁对谁生效」，产生位移/产出/代价
```

### 3.2 系统清单

| 系统 | 输入 | 输出 | 节拍 | 瓶颈 |
|---|---|---|---|---|
| 采集区 | 时间 / 鬼的动作 | 掉落物、垃圾 | 轮询 | 掉落率（面积参数比） |
| 物流（线 + 缓冲） | 掉落物 | 送达下游的物品 | 每 tick 步进 | 缓冲容量 |
| 加工鬼 | 输入形态物品 | 输出形态物品（带损耗） | 配方 cycle_time | 转化速率 |
| 岔口鬼 | 物品流 | 两条 1:1 支路 | 每 tick | 分流比固定 |
| 供品口 | 匹配形态的物品 | 分数 | 到达即结算 | 交付量 |
| **产能区** | 无（自持） | **鬼能** | **舌头 CD** | **链长 ÷ CD** |
| 共鸣判定 | 端口匹配 | 状态变化 + 代价 | 事件驱动 | 邻接与标签 |
| 空间预算 | 鬼 + 线的占格 | 限制 | — | **总格数** |
| 关卡流程 | 时间 + 交付量 | 星级 + 解锁 | 实时 | 限时 |

## 4. 核心循环

```
关卡开始 → 获得初始鬼能
   ↓
拖鬼到地图 → 连线 → 鬼开始运转
   ↓
采集区掉料 → 鬼吸收 / 加工 → 沿线传输 → 供品口交付
   ↓
交付计分 + 产能区产鬼能 → 继续造鬼 / 扩链 → 产线扩张
   ↓
限时内交付达标 → 结算星级 → 解锁新鬼
```

单局 4~6 分钟；Demo 3 关约 5 分钟。

**玩家的核心问题（贯穿全局）**：

> 有限格子里，铺一条快而脏的长线，还是造一条长而慢的产能链？

## 5. 资源与经济系统

### 5.1 鬼能：唯一的建造货币

〔定〕取消全局固定的「魂 / 鬼能 / 供品」三级资源。**鬼能是全局唯一的硬货币**，用于建造鬼与线。

### 5.2 物品按关卡定义的「形态」流转

〔定〕每一关的交付物、可用形态、地图布局**都不同**，全部是**关卡级数据**，不是全局常量。

| 概念 | 定义 | 落地 |
|---|---|---|
| **形态 (Form)** | 物品的类别标签，全局词表、关卡引用 | `Data/Forms/*.tres` |
| **配方 (Recipe)** | 形态→形态的转换规则，**转换只能由配方决定**，不能自由转 | `Data/Recipes/*.tres` |
| **供品口 (Terminal)** | 接受指定形态并计分的鬼 | 关卡数据指定位置与接受形态 |

**为什么这样分层**：难度曲线靠**加概念**而不是加数字。关 1 纯输送 → 关 2 加加工 → 关 3 加分流 + 产能区。每关只新增一个可理解的维度。

### 5.3 两条经济线（红线 6）

| | 产出物 | 来源 | 用途 | 消耗 |
|---|---|---|---|---|
| **鬼能线** | 鬼能 | **产能区**（自持引擎） | 造鬼、造线 | 建造 |
| **交付线** | 供品（计分） | 采集 → 加工 → 供品口 | 达成关卡目标 | 不消耗鬼能 |

〔定〕**两者互不依赖**：产能区不产供品，交付线不产鬼能。玩家的每一格预算都要在「造引擎」和「造产线」之间分配。

**为什么必须解耦**：如果只有一条经济线，玩家只有一个优化方向（把那条线做到极致），很快就腻。两条线各自有独立的瓶颈（引擎受 CD 限，产线受缓冲限），才能产生「我该先扩哪边」的真取舍。

### 5.4 加工损耗

〔定〕加工**带损耗**，差额变为垃圾。

| 字段 | 示例 | 说明 |
|---|---|---|
| `input_form` | Raw | 输入形态 |
| `output_form` | Processed | 输出形态 |
| `cycle_time` | 1.2 s | 转换耗时 |
| `yield_rate` | 0.8 | 产出比例，差额为损耗 |

**损耗的意义**：让加工链自带垃圾来源。垃圾因此不是孤立的惩罚，而是**全系统效率的残渣**——它堵缓冲 → 背压 → 逼迫玩家重排布。

**UI 要求**：必须明确显示「输入 5 / 产出 4 / 损耗 1」，否则玩家会以为喂够了却少交了一份。

### 5.5 形态分流

〔定〕第 3 关起，供品口接收**不同形态**，玩家必须用岔口鬼把产线拆成两条支路。

```
          ┌→ 供品口 A（收 Raw）
料源 → 岔口 ┤
          └→ 供品口 B（收 Processed，经加工鬼转换）
```

〔定〕**岔口鬼比例固定 1:1**，不可调。要改变某条支路的形态，靠在该支路上放加工鬼。这样分流与加工形成组合深度，而不是数值滑条。

## 6. 地图与空间管理

### 6.1 地图是预先设计好的

〔定〕**地图由设计者预先做好**：固定的小网格地图，包含地形、障碍、可用区域。玩家在既定地图里布置鬼和线。

- 玩家**不能**在运行时改变地形或自由塑形可建区。
- 地图尺寸逐关设计时决定，**本策划不固定数值**。

**为什么固定地图是好事**：难度变成关卡设计问题而非玩家的空间管理问题；地形可以设计成「看似通的路实际堵死」「必须绕远」这类具体谜题；玩家的决策空间收窄到可控范围，更适合关卡制。

### 6.2 空间预算

〔定〕地图上**可用格数有限**（地形格不可用），鬼和线都占用可用格。

| 项 | 规则 |
|---|---|
| 节点鬼 | 占 1 格 |
| 采集鬼 | 占其采集区的实际格数 |
| **线** | **每经过 1 格占 1 格；拐弯的角格只算一次，不额外加** |

〔定〕「线占一格，拐弯不占」——即线经过的格子数（含拐角格，每格仅计一次）就是它的空间开销。

**线的占位是空间管理的核心决策点**：一条绕远的线可能吃掉 6 格，直接决定玩家能放几只鬼。

### 6.3 空间预算初值

〔初〕逐关收紧曲线（待具体关卡设计时校准）：

| 关 | 建议可用格 |
|---|---|
| 第 1 关 | 12 |
| 第 2 关 | 18 |
| 第 3 关 | 24 |

## 7. 物流系统（线 / 缓冲 / 背压）

> 本节是此前缺失的系统层，是「产线游戏」与「数字游戏」的分界。

### 7.1 线的构成

〔定〕**线也是一种鬼**，它有自己的实体，传输物料。

| 项 | 规则 |
|---|---|
| 走向 | 正交（上下左右）折线，不能斜 |
| 方向 | **有向**——从上游流向下游 |
| 端点 | 上游接鬼的**输出端口**，下游接鬼的**输入端口** |
| 拐弯 | 允许；拐角格只计一次空间 |
| 交叉 | 〔待〕允许，交叉处减速（倾向） |
| 容量 | 〔初〕每段线上最多容纳 **3 个物品** |

### 7.2 物品移动

〔定〕**离散格步进**，不是连续插值移动。物品每 tick 前进一格。

理由：整个游戏是「一次一次像机关」的节奏（舌头伸出、鬼吞吐、交付），连续插值会引入与网格不匹配的平滑动画，且难以与 tick 逻辑对齐。物品在格与格之间「跳」反而更有工业节拍感。

〔初〕物品步进频率：每 **0.3 s** 前进一格（即线速约 3.3 格/秒）。

### 7.3 缓冲与背压

〔定〕每只鬼有**输入缓冲**与**输出缓冲**，容量按鬼不同（1~3 格）。

**背压规则（连锁阻塞）**：

```
输出缓冲满
  → 该鬼停止接受上游物品（输入缓冲不再抽取）
  → 输入缓冲逐渐填满
  → 输入缓冲满
  → 该鬼停止从上游线取货
  → 上游线的物品堆满（线容量 3）
  → 上游鬼的输出缓冲填满
  → 继续向上游传播阻塞
  → 采集区吸不走料 → 掉落物在采集区堆积
```

〔定〕**这条链是自动的，不需要玩家干预**。玩家的应对方式是重排布局、减少上游供给、或加收容鬼清理垃圾腾出缓冲。

〔初〕缓冲容量初值：

| 鬼 | 输入缓冲 | 输出缓冲 |
|---|---|---|
| 采集鬼（贪食/细嚼） | — | 3 |
| 灶鬼（加工） | 3 | 3 |
| 岔口鬼 | 3 | 3 |
| 供品口 | 6 | — |
| 长舌鬼 | — | 2 |

### 7.4 掉落物与垃圾的实体性

〔定〕**掉落物和垃圾都是真实实体**，占据地图格子。

- 掉落物：采集区内的物品堆，等待被采集鬼吸收。
- 垃圾：加工损耗或采集鬼产生的废物，**占据所在格的缓冲容量**，必须被收容鬼吃掉才能腾出。
- 〔定〕两者数值上**均无上限**（不会因为太多而卡死逻辑）。

〔定〕**视觉上限 = 纯表现层的堆叠压缩**，不改变任何逻辑：
- 同一格最多画 5 个物品图标
- 超出后显示 `×N` 角标，N 为真实数量
- 数值完全准确，仅视觉不糊

〔初〕压缩阈值：同格 5 个图标后转 `×N`。

### 7.5 背压的可见性

〔初〕玩家必须能看出哪里堵了，否则背压变成不可解的死局：

| 信号 | 表现 |
|---|---|
| 缓冲满 | 鬼身上出现警示图标（脉冲） |
| 线满 | 线段上物品变红 / 闪烁 |
| 采集区堆积 | 采集区内物品堆叠变高 |

〔定〕这些只是提示，不改变逻辑。

## 8. 采集系统

### 8.1 采集区形状自由，但有参数比

〔定〕采集鬼占据一个**玩家可自由拖出形状**的区域。

〔定〕**不是越大越好**：面积与效率之间存在参数比（边际递减）。

**形状与面积是两个独立的决策**：

| | 影响什么 |
|---|---|
| **形状** | 掉落点覆盖到哪（够得到哪些地块） |
| **面积** | 总掉落量（产能） |

〔初〕**总掉落率公式**：`total_rate = base_rate × area ^ efficiency`，其中 `efficiency < 1`。

示例（`base_rate = 0.5`，`efficiency = 0.5`）：

| 面积 | 总掉落率 | 每格效率 |
|---|---|---|
| 4 格 | 1.0 /s | 0.25 /s |
| 9 格 | 1.5 /s | 0.167 /s |
| 16 格 | 2.0 /s | 0.125 /s |

**关键设计约束**：形状对总量**无影响**。若形状还影响产量，「自由形状」就只是绘制自由，没有决策价值。

### 8.2 两个采集鬼变体

〔定〕一个快但会暴垃圾，一个慢但不会暴垃圾。

| | 贪食鬼 | 细嚼鬼 |
|---|---|---|
| 形状 | 自由 | 自由 |
| 基础掉落率 | 高 | 低 |
| 垃圾率 | 40% | 0% |
| 建造造价 | 12 鬼能 | 8 鬼能 |

两个维度的取舍：**速度换空间 + 污染**（贪食鬼占格多还带垃圾）vs **效率换时间**（细嚼鬼占格少但喂不饱）。

### 8.3 掉落触发

〔定〕两种触发源并存：

| 触发源 | 用于 | 效果 |
|---|---|---|
| 时间轮询 | 采集鬼 | 区域内随机位置掉一个料 |
| **动作触发** | 节点鬼 | 鬼完成一次有效动作 → 掉一个料 |

动作触发让「鬼在动」与「料在来」绑定，节奏感强，且天然防卡（鬼在动就有料）。

## 9. 鬼的系统

### 9.1 三种形态

| 类型 | 占地 | 行为 |
|---|---|---|
| **节点鬼** | 1 格 | 参与连线与共鸣 |
| **采集鬼** | 自由形状区域 | 框定区域产生掉落物并吸收 |
| **供品口** | 1 格 | 接受指定形态并计分（也是鬼，不设独立系统层） |

### 9.2 鬼表

| 鬼 | 端口 / 反射 | 自动/手动 | 独特规则 |
|---|---|---|---|
| **长舌鬼** | ACTION `GRAB`；RECEPTACLE `SWALLOW` | 自动 | **本体固定不动**；舌头固定一格，像 MC 活塞按 CD 周期伸缩；推挤链的起点 |
| **吊死鬼** | ACTION `HANG`；RECEPTACLE `GRAB` | **手动**（点一下挂上吊绳） | 挂上后自动荡回，承担推挤链的中继 |
| **不倒翁鬼** | 反射 `MOVE` → 产鬼能 | 自动 | 被动位移即产能；产能区的主要产能源 |
| **灶鬼**（加工鬼） | ACTION `FEED`；RECEPTACLE `SWALLOW` | 自动 | 执行 Recipe，形态转换，带损耗 |
| **岔口鬼** | ACTION `SPLIT` | 自动 | 一分为二，固定 1:1 |
| **贪食鬼** | 采集鬼 | 自动 | 快、暴垃圾 |
| **细嚼鬼** | 采集鬼 | 自动 | 慢、干净 |
| **收容鬼** | 反射 `BUFFER_FULL` → 吃垃圾 | 自动 | 清垃圾释放缓冲 |
| **镜鬼** | ACTION `MIRROR`；反射 `NEIGHBOR_CHANGED` → 复制邻居端口 | 自动 | 复制品减半 + 8 s 寿命 |
| **供品口** | RECEPTACLE `OFFER` | — | 接受指定形态并计分 |
| **线** | 连线实体（也是一种鬼） | — | 传输物料，受空间预算限制 |

**手动鬼的统一形态**：

〔定〕手动鬼都是**一次性开关式**，而非持续连点：

| 鬼 | 手动行为 | 不操作的后果 |
|---|---|---|
| 吊死鬼 | 点一下 → 挂上吊绳 | 没挂上 = 不参与推挤链，不被推也不中继 |

〔待〕是否需要「持续按住型」手动鬼（如必须按住才出货）。**倾向不引入**——持续按住会让游戏变成体力活，与红线 3 冲突。

### 9.3 长舌鬼：活塞舌

〔定〕**长舌鬼本体固定不动，动的是舌头。舌头固定死一格，行为等同 Minecraft 活塞。**

MC 活塞语义：伸出 → 推动前方一格的方块 → 收回（方块留在原处；被抓住的会被拖回）。

〔定〕**推拽不需要代价**——推和拽本身免费。

**周期动作**（〔初〕约 2.0 s 一轮：伸出-停留-收回-停留）：

```
① 舌伸入舌格 → 推动舌格内的鬼 1 格（触发其位移反射）
② 舌缩回 → 若舌抓着鬼，跟着被拖回 1 格（再次触发位移反射）
③ 舌格里的料送入自己连接的产线
```

**这条推挤循环是自持的产能引擎，不需要外部驱动。**

一只长舌鬼 + 吊死鬼 + 不倒翁鬼 组成一台持续产鬼能的机器——**这是设计意图，不是风险**。这个组合称为「产能区」，是玩家主动要造的东西。

**限制不在于会不会停，而在于够不够快、够不够长**：

| 限制来源 | 含义 |
|---|---|
| **舌头周期 CD** | 一次推挤循环时长，决定基础产能速率 |
| **推挤链长度** | 一次推挤能推动几只鬼（见 9.4） |
| **空间预算** | 产能区占格子，与产线抢同一份空间 |

**为什么本体固定是对的**：鬼能跑的话玩家会盯着鬼看，本体固定则玩家盯着产线看——后者才是工厂游戏该有的视角。

### 9.4 产能区：推挤链

〔定〕**推挤是连锁的**——被推的鬼会撞到它前方的鬼，把推力传下去。这条链上的每只鬼都会产生一次位移事件。

```
长舌鬼 → 吊死鬼 → 不倒翁鬼 → 不倒翁鬼
  推      推        产鬼能      产鬼能
```

**产能区 = 长舌鬼 + 一条被推挤的链，链上每只不倒翁鬼各产一次鬼能。**

```
一次循环（约 2 s）产出 = 链上不倒翁鬼的数量 × 单只产能量
产能速率 = 链上不倒翁鬼数 ÷ 舌头 CD
```

**这就是「产能区」的取舍结构**：

| 想要更多鬼能 | 代价 |
|---|---|
| 链上多塞几只不倒翁鬼 | 多占格子 → 挤掉产线空间 |
| 缩短舌头 CD | 单次产能量不变，但节奏更密 → 手感压力更大 |
| 让吊死鬼成为中间传力者 | 多占 1 格，但能维持链条继续往后传 |

**链为什么需要中间传力者**：不倒翁鬼自己也会被推走。推挤是「推前方的鬼」，所以最前面那只要么被推走、要么推回来就卡住。吊死鬼的作用是**被推出去又自己荡回**（吊着的东西会晃），承担中继。

〔定〕**吊死鬼的回位是自动的**——由其 `HANG` 端口自作用完成（`ACTION HANG` 命中自身 `RECEPTACLE HANG`）。玩家的手动操作只发生在**第一次挂上吊绳**。

**代价（红线 1）**：产能区的主要代价是**空间**——它与产线抢同一份预算。这比"产出打折"更硬，因为空间是不能靠技术绕过的真稀缺。

### 9.5 后续规划鬼（长期，不进 Demo）

| 鬼 | 动词 | 独特规则 | 代价 |
|---|---|---|---|
| 鼓鬼 | 搏动 | 全场鬼按节拍同时触发一次共鸣 | 消耗自身充能 |
| 溺鬼 | 渗漏 | 邻格线缆漏水，线上物料会流失 | 漏水范围随等级扩大 |
| 缚鬼 | 束缚 | 固定相邻鬼的位置使其不能被移动 | 固定后不可再共鸣 |
| 算盘鬼 | 增值 | 给经过的货物记价，交付时翻倍 | 每记一次自身积攒负面状态 |
| 甲背鬼 | 搬运 | 唯一能跨越障碍传输 | 极慢，占用大量缓冲 |

### 9.6 设计约束

- 每只鬼只能有 **一个** 独特机制，且必须与工业化叙事自洽（长舌＝收集、镜＝复制、吊死＝吊挂）。
- 鬼总数控制在 12~15 只，靠标签组合撑起变化，而不是靠数量。
- 同一只鬼在不同邻居组合下行为不同 → 拓扑决策有深度。

## 10. 共鸣系统

### 10.1 三层接口模型

**不写死**是硬要求：新增一只鬼只写数据，不改核心逻辑。分三层：

**第 1 层 · 端口（开放词表，有方向）**

| 方向 | 含义 |
|---|---|
| `ACTION` | 我能作用于什么（施加方） |
| `RECEPTACLE` | 我能被什么作用（承受方） |

判定：鬼 A 的 `ACTION` 端口命中邻居的 `RECEPTACLE` 端口 → 触发。

一只鬼可以有多个端口、多种方向，不限于「提供 / 需要」两组。

**第 2 层 · 反射（条件句）**

反射 = `当 [事件] 发生于我 → 执行 [效果]`。事件类型同样开放：

| 事件 | 触发时机 | 用它的鬼 |
|---|---|---|
| `MOVE` | 自身位置发生变化 | 不倒翁鬼、吊死鬼 |
| `ACTED_ON` | 自己被别人作用 | 通用 |
| `BUFFER_FULL` / `BUFFER_EMPTY` | 缓冲满 / 空 | 收容鬼等 |
| `NEIGHBOR_CHANGED` | 邻居变化 | 镜鬼 |
| `TICK` | 每秒 | 通用 |

**第 3 层 · 场域**

采集鬼占据矩形区域，区域内产生掉落物，从输出端口送出。

### 10.2 条件消耗式触发（无冷却）

〔定〕**共鸣不需要冷却**。正确解法不是限流，而是**让条件本身具备门槛**。

| 条件类型 | 含义 |
|---|---|
| `ON_ACTION_DONE` | 触发者完成一次动作（如长舌鬼舌头伸出一次） |
| `ON_ENTER_CELL` | 触发者移动到指定相邻格 |
| `ON_STATE` | 触发者进入某状态（手持物 / 缓冲非空） |
| `COMPOSITE` | 多个条件同时满足（AND） |

**机制**：条件满足 → 结算 → **条件重置**，需再次满足才能再次触发。

**为什么不需要冷却**：条件本身就是门槛。推挤链的触发条件是「舌头伸出」这个动作，而舌头按自己的 CD 周期伸出——**CD 就是限流器**。条件消耗式与 CD 是同一件事的两面：条件保证「一次动作只结算一次」，CD 保证「一个周期只动作一次」。

机关式比冷却好：冷却是「你不许太快」，机关是「它本来就只这么转」。前者是限制，后者是节奏。

**两类共鸣的驱动力不同**：

| 类型 | 驱动力 | 例子 |
|---|---|---|
| **自持型** | 鬼自己的周期动作（CD） | 产能区：长舌鬼舌头周期推挤链 |
| **物流型** | 上游物料供给 | 灶鬼吞吐、岔口鬼分流 |

自持型不耗料，靠 CD 限速；物流型消耗料，靠供给限速。**产能区属于前者**——它是鬼能的主要来源，是玩家主动造的引擎。

### 10.3 共鸣的代价（不可省略）

每种共鸣**必须**附带至少一项代价：

| 代价 | 说明 |
|---|---|
| **空间占用** | 产能区与产线抢同一份空间预算（最硬的代价，不可绕过） |
| 产出打折 | 共鸣期间产出 ×0.5 |
| 产生垃圾 | 产出的一部分变成垃圾，垃圾占缓冲 |
| 寿命限制 | 共鸣态持续 N 秒后强制解除 |
| 占位 | 共鸣中的鬼无法再与其他鬼共鸣 |
| 反向效果 | 共鸣对双方一增一减 |

〔待〕每条共鸣规则具体用哪种代价，逐条在 `Data/Resonance/*.tres` 中确定。

### 10.4 标签库

〔定〕标签**不写死**，存于数据文件。已用到的：

| 标签 | 含义 | 相关鬼 |
|---|---|---|
| `GRAB` | 攫取 / 拉扯 | 长舌鬼（ACTION）、吊死鬼（RECEPTACLE） |
| `HANG` | 悬挂 / 吊挂 | 吊死鬼（ACTION + RECEPTACLE，自作用回位） |
| `SWALLOW` | 吞噬 | 长舌鬼、灶鬼（RECEPTACLE） |
| `FEED` | 投喂 / 炼化 | 灶鬼（ACTION） |
| `SPLIT` | 分流 | 岔口鬼（ACTION） |
| `MIRROR` | 映照 / 复制 | 镜鬼（ACTION） |
| `OFFER` | 交付 | 供品口（RECEPTACLE） |

### 10.5 共鸣示例

**长舌鬼 ⇄ 吊死鬼**
- 长舌鬼 `ACTION GRAB` 命中吊死鬼 `RECEPTACLE GRAB` → 舌头推挤吊死鬼
- 效果：推力沿链传递，链上每只不倒翁鬼 `MOVE` 反射 → 产鬼能
- 代价：**占用格子**——产能区与产线抢同一份空间预算

**长舌鬼 ⇄ 镜鬼**
- 镜鬼 `ACTION MIRROR` 复制相邻鬼的端口 → 长舌鬼与自己共鸣
- 代价：复制品产出减半 + 8 秒寿命（时间与品质双重限制指数增长）

## 11. 建造与编辑系统

> 本节此前缺失，定义玩家如何操作。

### 11.1 放置鬼

〔定〕从底部鬼牌栏**拖到地图**放置。

| 校验项 | 规则 |
|---|---|
| 格子可用 | 目标格必须在地图可用区内 |
| 不重叠 | 目标格及其采集区不能与已有鬼重叠 |
| 鬼能充足 | 造价 ≤ 当前鬼能；不足时牌栏置灰 |
| 空间足够 | 放置后总占用 ≤ 空间预算 |

〔定〕**放置失败给出明确反馈**（格子闪红 / 提示文字），不静默失败。

### 11.2 连线

〔定〕**从鬼的输出端口拖到另一个鬼的输入端口**建立连接。

| 规则 | 说明 |
|---|---|
| 方向 | 输出 → 输入，不可反向 |
| 路径 | 正交折线；玩家拖出的拐弯格计入空间 |
| 一进一出 | 〔初〕每只鬼默认 1 个输出、1 个输入；岔口鬼 1 进 2 出 |
| 校验 | 目标必须接受该形态（否则提示「该口不收此形态」） |

〔初〕连线交互的简化方案：玩家先点源鬼的输出端口，再点目标鬼的输入端口，系统自动生成 L 形路径；**若空间不够或路径不通，提示并拒绝**。比让玩家手绘折线简单得多，且空间成本自动可见。

### 11.3 编辑与拆除

| 操作 | 行为 |
|---|---|
| 拆除鬼 | 点击鬼 → 拆除 → 释放其占格；〔待〕是否全额退还鬼能 |
| 拆除线 | 点击线段 → 拆除 |
| 移动鬼 | 〔定〕**仅在关卡暂停时可移动**（见 §12）；运行中不可拖动（红线 5） |

〔初〕**拆除全额退还鬼能**。理由：鼓励玩家试错与重排，这是拓扑玩法的乐趣来源；扣押金会让玩家不敢动，破坏"布局即决策"的核心。

### 11.4 建造时游戏是否继续运行

〔待〕**关键体验决策**。

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 建造时继续运行 | 紧张，边造边被时间追 | 玩家思考时被迫分心，且移动鬼受限 |
| B. 建造时自动暂停 | 思考从容 | 失去压力，限时变得无关紧要 |

〔初〕**倾向 A，但提供「规划模式」快捷键**：按住某键（或点 UI 按钮）临时暂停并自由移动鬼，松开恢复。这样紧张与从容都能拿到。

〔待〕这个决定影响关卡限时数值，需你拍板。

## 12. 运行循环与时间规则

### 12.1 Tick 顺序

〔定〕固定顺序执行，保证判定可预期：

```
1. 采集掉落      —— 采集区按轮询率生成掉落物
2. 鬼动作        —— 推进 CD 到期的鬼（舌头伸缩、吞吐、分流）
3. 位移结算      —— 推挤链的连锁位移，逐个结算 MOVE 反射
4. 共鸣判定      —— 端口匹配 + 条件检查，结算共鸣与代价
5. 物流推进      —— 物品在线上步进一格，背压自上游向下游传播
6. 加工/交付     —— 加工鬼转化（计损耗）、供品口接收并计分
7. 缓冲/垃圾结算 —— BUFFER_FULL 等状态触发反射（如收容鬼吃垃圾）
8. UI 刷新       —— 资源条、缓冲警示、倒计时
```

〔定〕**顺序不可交换**：先动作后位移（舌头推人产生位移），先位移后共鸣（位移触发反射），先共鸣后物流（共鸣改变吞吐）。

### 12.2 Tick 频率

〔定〕逻辑与渲染分离，逻辑固定频率。

〔初〕逻辑 tick = **20 Hz**（0.05 s）；渲染独立。

理由：20 Hz 足够让 0.3 s 的物品步进稳定落在 6 个 tick 上，不会出现「有时 6 步有时 5 步」的抖动。

### 12.3 暂停

〔定〕以下情况暂停游戏逻辑：
- 打开设置面板
- 教程对话框正在显示
- 玩家主动进入规划模式（§11.4）

〔定〕暂停时**保留所有状态**，恢复后继续；不重置 tick 计时。

### 12.4 时间与失败

| 项 | 规则 |
|---|---|
| 限时 | 每关独立配置（〔初〕90 / 120 / 120 s） |
| 倒计时归零 | 若已达交付目标 → 结算；否则 → 失败 |
| 失败 | 可重试，不扣任何东西（不消耗解锁） |

〔定〕**失败不惩罚**。因为关卡内不存档、局外只有解锁表，惩罚无处安放；惩罚只应来自"时间不够"这一压力本身。

### 12.5 结算

〔定〕关卡结束时展示：
- 三轴评分（效率 / 手动 / 空间）+ 星级
- 本关解锁的新鬼 / 形态 / 配方
- 「重试」「下一关」「返回」按钮

## 13. 关卡结构

### 13.1 关卡内是谜题，关外是解锁表

- **关卡内**：限时 + 目标 + 三轴评分
- **关外**：**每关自动解锁**下一项，无货币、无攒点

〔定〕局外层**不做局外货币**。局外货币会引入「这局要不要多刷点」的元游戏，与产线专注度冲突，并催生「一条科技线不断处理」。

### 13.2 评分三轴

| 轴 | 含义 | 引导的设计 |
|---|---|---|
| 效率 | 单位时间交付量 | 造线紧凑、少冗余 |
| 手动 | 完成所需点击次数 | 逼玩家优化共鸣组合而非硬点 |
| 空间 | 占用格数 / 可用格数 | 逼玩家做取舍而非铺满 |

三轴对应三套系统（物流 / 注意力 / 拓扑），评分表本身就是给玩家的优化指南。

星级：1★ 达标；2★ 达到基准时间；3★ 三轴同时达标。

### 13.3 难度曲线（按概念递增，不按数值递增）

| 章 | 主题 | 新增概念 |
|---|---|---|
| 1 | 学会一条链 | 放置、连线、吞吐、交付 |
| 2 | 学会加工 | 形态、配方、损耗、垃圾、背压 |
| 3 | 学会造引擎 | 产能区、推挤链、空间取舍 |
| 4 | 学会分流与复制 | 岔口鬼、镜鬼 |
| 5 | 综合 | 多目标、严限时、窄地形 |

### 13.4 Demo 三关（约 5 分钟）

| 关 | 时长 | 教什么 | 引入 |
|---|---|---|---|
| 第 1 关 | ~90 s | **纯输送**，只介绍基本设定与玩法：拖放、连线、自动运转、交付 | 长舌鬼、供品口 |
| 第 2 关 | ~120 s | 加工：形态转换、损耗、垃圾、背压 | 灶鬼、贪食鬼、收容鬼 |
| 第 3 关 | ~120 s | **产能区 + 形态分流**：造推挤链产鬼能，同时两供品口收不同形态必须分线 | 岔口鬼、吊死鬼（手动）、不倒翁鬼 |

镜鬼与细嚼鬼挪到后续章节，Demo 不做。

〔初〕**第 1 关是否留一个「两只鬼会互动」的信号**：约 5 秒的位移反射闪一下 + 鬼能 +3 + 一句对话框。理由：纯输送关不给出任何互动信号，玩家会以为这是搬东西游戏，而这正是本作的卖点。若要绝对干净，则挪到第 2 关开头作引子。

## 14. 元进度

〔定〕**局外层 = 解锁表，每关通过后自动解锁下一项。** 无货币、无攒点。

| 解锁项 | 作用 | 何时 |
|---|---|---|
| 新鬼 | 可放置的新规则单元 | 主体 |
| 新形态 | 关卡可用的物品形态 | 第 2 关解锁 Processed |
| 新配方 | 形态转换规则 | 第 2 关解锁 RawToProcessed |
| 新机制 | 如「槽位可解锁」「线可升级」 | 后期 |

## 15. 教程系统

〔定〕**形式 = 对话框 + 聚光灯遮罩**（周围变黑，中间标亮目标）。

**实现要点**：
- `CanvasLayer` + 全屏半透明黑 `ColorRect` + 上方挖亮区。亮区用 `Control` 圆形遮罩（Shader 或 `Light2D` + 遮罩贴图）。
- 亮区跟随目标节点世界坐标实时更新，目标移动时亮区跟随。
- 流程：点继续 → 亮区移到下一目标 → 完成指定操作 → 对话框继续。
- 可跳过（设置项「已看过的教程段落不再重复」）。
- **教程内容与关卡数据绑定**，放在关卡配置里，不硬编码在 UI 脚本中。

**教学只覆盖必要**：拖放、连线、点击手动鬼、交付。

〔定〕教程对话框显示期间**游戏暂停**（见 §12.3）。

## 16. 存档

〔定〕**完整存档**，含进度、解锁、设置。

| 段 | 内容 |
|---|---|
| `version` | 存档版本号，用于迁移 |
| `progress` | 已解锁关卡、每关最佳星级、当前所在关 |
| `unlocked_ghosts` | 已解锁鬼列表 |
| `unlocked_forms` / `unlocked_recipes` | 已解锁形态与配方 |
| `settings` | 音量、教程跳过标记、震动/特效开关 |
| `meta` | 累计游玩时长、通关次数 |

**原则**：
- 通过 `SignalBus` 广播变化，实体用 `ExportSaveData() -> Dictionary` / `LoadSaveData(data: Dictionary) -> void` 序列化（遵循 `src/AGENTS.md` 第四节）。
- **关卡中途退出不保存**（关卡内状态是瞬态），只保存进度与设置，避免存档一致性难题。
- **音量设置沿用现有 `user://audio_settings.cfg`**（`Util.gd` 已实现），不重复造；总存档另用 `user://savegame.cfg`。
- 写入时机：解锁新鬼 / 关卡结算 / 设置变更 / 退出游戏。

## 17. 音频与设置

**音频总线**（`default_bus_layout.tres` 已配）：`Master / Music / SFX / Dialogue / Ambience`。

**设置面板可调项**：
- 总音量、音乐、音效、对白、环境音 —— 各自独立滑条，实时生效并持久化
