# 鬼工厂 — 策划案

> 状态：核心玩法已定，Demo 范围已切。美术与音乐风格暂缺，后续补写。
> 技术栈：Godot 4.7.2，仓库 `src/` 为 Godot 工程根，`res://` = `src/`。
> 本文档为项目设计事实来源，与 `src/AGENTS.md` 的代码规范配套使用。

---

## 1. 一句话定位

> **每个鬼不是一台机器，而是一条规则。**
> 玩家用鬼的规则搭出一条会自己运转的产线；两只鬼互相满足对方的规则时发生「共鸣」，共鸣才是鬼能的主要来源。

与同类产品的差异：

| 参照物 | 它做什么 | 本作差异 |
|---|---|---|
| 《沙金工业》(Satisfactory) | 物流吞吐与资源分流，机器是主角 | 鬼是规则而非机器；能量来自规则互喂而非机器耗电 |
| 《末日电涌》(Rogue Voltage) | 模块互相连线成环，模块互触发电 | 同样的循环链，但主题是鬼，且共鸣带代价 |
| 《工厂》(Factory Fun) | 连线本身给奖励 | 只在连线的瞬间给一次性奖励，没有持续运转 |
| Opus Magnum | 机械臂互顶、压力传递 | 同样讲互作用，但它是解谜式单解，不是产线吞吐 |

**关键结论**：两个规则单元互为能源、以拓扑方式组合，这个层次市面上是空的。这是本作的卖点。

## 2. 设计目标与红线

**要证明的核心乐趣**：把两只鬼贴在一起会「来电」，而且这个电足以让玩家做出有代价的选择。

**红线**（踩了就毁掉核心）：

1. **鬼之间必须有取舍，不能只有增益。** 每种共鸣至少附带一项代价（产出打折、产生垃圾、寿命限制、占位）。
2. **共鸣必须靠空间拓扑产生，不靠数值堆叠。** 加鬼要重新排布，不是加一层。
3. **手动操作是节拍器，不是主要产能来源。** 手动鬼占产量瓶颈，但不占产能主体，否则退化成手速游戏。
4. **不做纯数值科技树。** 元进度只解锁新鬼，新鬼带来的是新规则，不是 +10%。

## 3. 核心循环

```
关卡开始 → 获得初始鬼能
   ↓
拖鬼到网格 → 连线 → 鬼开始运转
   ↓
喂原料 → 鬼产出鬼能/中间物 → 经线传输 → 供品口交付
   ↓
鬼能积累 → 继续造鬼 / 升级 → 产线扩张
   ↓
限时内交付达标 → 结算星级
   ↓
解锁新鬼 → 下一关引入新规则
```

单局 4~6 分钟；Demo 3 关约 5 分钟。

## 4. 资源系统（三种）

| 资源 | 代号 | 角色 | 说明 |
|---|---|---|---|
| 鬼能 | `ENE` | 建造货币 + 核心产出 | 放置鬼、连线、升级都消耗它；关卡目标也以它计量 |
| 魂 | `SOUL` | 原料 | 地图上生成，被鬼消耗；不直接计入目标 |
| 供品 | `OFFER` | 交付物 | 只有供品口接受；由中间物加工而来 |

**为什么是三种**：鬼能负责「建造与产出」这一层，魂负责「投入」，供品负责「交付」。三者分别对应工厂模拟的三个面：产能、原料、成品。少于三种会退化成一个数字的堆叠，多于三种 Demo 阶段UI 与认知都扛不住。

**规则**：
- 鬼能既是货币又是目标 → 玩家天然会纠结「再攒一台鬼还是直接过关」。这个矛盾是免费的、好的关卡张力来源。
- 供品只由供品口消费，囤积无意义 → 逼迫玩家打通全链路，而不是只堆前半段。
- 魂从地图生成点持续产出，是唯一的时间压力源。

**中间物不占资源位**：长舌鬼吞魂吐出「气」，灶鬼把气炼成「供品」——气只是网格上的货物，不是第四种资源。这样既保留了「持续分流处理」的流水线观感，又不让 UI 多一栏。

## 5. 网格、产线与背包感

**网格**：12×8 起（关卡可缩放到 10×6 / 14×8）。网格是共鸣判定与布局规划的空间基础。

**连线（固定线）**：鬼之间用定向线连接，线有容量上限。

**缓冲与背压（背包感的来源）**：
- 每只鬼有 1~3 格内部缓冲（不同鬼不同）。
- 线上货物有容量限制。
- **缓冲满时上游被阻塞**，下游断料则停摆。

这一条是「产线游戏」与「数字游戏」的分界线：缓冲满了，加产线的鬼没用，必须**分流**或**提高下游速度**。这自然逼出拓扑决策，而不是一条直线堆到底。

**三资源的流转位置**：
- 魂：地图生成点 → 线 → 鬼的嘴
- 鬼能：鬼产出 → 立刻进账（不进线，避免玩家手动搬运）
- 供品：线 → 供品口

## 6. 共鸣系统（核心）

### 6.1 标签模型

每只鬼声明两个标签集：

- **提供标签**（`provides`）：我能给别人什么
- **需要标签**（`needs`）：我需要别人给我什么

**共鸣判定**：当鬼 A 与鬼 B 在网格上相邻（4 邻），且 `A.provides ∩ B.needs ≠ ∅` 时，二者发生共鸣。

标签不是两两特判的硬编码，而是数据驱动：新增一只鬼只需声明标签，配对关系自动成立。加到 30 只鬼不会有 900 个 case。

### 6.2 共鸣事件

每次共鸣产生一个 **共鸣事件**：

```
共鸣事件 {
  参与者: [鬼A, 鬼B]
  触发标签: StringName
  产出: 鬼能 +N
  附加效果: 对 A、B 各自施加状态（增速 / 减速 / 产出打折 / 产生垃圾 / 寿命倒计时）
  冷却: 该对鬼在 cooldown 秒内不再共鸣
}
```

**冷却是必需的**：没有冷却，共鸣会在同一帧被反复触发，指数级刷能。冷却让共鸣变成「节奏」而不是「事件洪水」。

### 6.3 共鸣的代价（不可省略）

每种共鸣**必须**附带至少一项代价。代价类型库：

| 代价 | 说明 | 典型用途 |
|---|---|---|
| 产出打折 | 共鸣期间产出 ×0.5 | 温和可接受的常规代价 |
| 产生垃圾 | 产出的一部分变成垃圾，垃圾会占用缓冲 | 制造空间压力，逼玩家取舍 |
| 寿命限制 | 共鸣态持续 N 秒后强制解除 | 逼玩家做节拍，不能永久挂着 |
| 占位 | 共鸣中的鬼无法再与其他鬼共鸣 | 制造「选谁不选谁」的拓扑取舍 |
| 反向效果 | 共鸣对双方一增一减 | 最硬核的取舍，适合高阶鬼 |

### 6.4 标签库（当前）

| 标签 | 含义 | 相关鬼 |
|---|---|---|
| `GRAB` | 攫取 / 拉扯 | 长舌鬼提供 |
| `HANG` | 悬挂 / 吊挂 | 上吊鬼提供 |
| `MIRROR` | 映照 / 复制 | 镜鬼提供 |
| `FEED` | 投喂 / 炼化 | 灶鬼提供 |
| `PULSE` | 搏动 / 节拍 | 鼓鬼提供（后续） |
| `WEEP` | 渗漏 / 溢流 | 溺鬼提供（后续） |
| `BIND` | 束缚 / 固定 | 缚鬼提供（后续） |

### 6.5 共鸣示例

**长舌鬼 ⇄ 上吊鬼**
- 长舌鬼：`provides = [GRAB]`，`needs = [HANG]`
- 上吊鬼：`provides = [HANG]`，`needs = [GRAB]`
- 共鸣效果：长舌鬼吞吐 ×2；代价：长舌鬼 30% 产出变成「残魂」垃圾；垃圾占缓冲。
- 玩家决策：忍受垃圾堆缓冲 / 放收容鬼清理 / 放弃这 50% 效率。

**长舌鬼 ⇄ 灶鬼**
- 灶鬼：`provides = [FEED]`，`needs = [GRAB]`
- 共鸣效果：长舌鬼的「气」直接被灶鬼吞掉加工成供品，省掉一段连线；代价：供品产出固定上限，不能靠堆鬼线性提升。

**长舌鬼 ⇄ 镜鬼**
- 镜鬼：`provides = [MIRROR]`，`needs = []`（无欲无求，但会复制邻居）
- 共鸣效果：镜鬼复制相邻鬼的 `provides` 标签 → 长舌鬼与自己共鸣。
- 代价：复制品产出减半，且只存在 8 秒。**时间与品质双重限制指数增长。**

## 7. 鬼图鉴

### 7.1 已定鬼（Demo 范围）

| 鬼 | 动词 | provides | needs | 自动/手动 | 独特规则 | 代价 |
|---|---|---|---|---|---|---|
| **长舌鬼** | 采集 | `GRAB` | `HANG` | 自动 | 吞魂，吐出「气」；是整条链的起点 | 与上吊鬼共鸣时 30% 变垃圾 |
| **上吊鬼** | 悬挂 | `HANG` | `GRAB` | **手动** | 本身不产鬼能，只提供吊挂；玩家点击「挂钩」才生效 | 不点击则完全不产出 |
| **灶鬼** | 转化 | `FEED` | `GRAB` | 自动 | 把气炼成供品 | 供品产出有硬上限 |
| **镜鬼** | 复制 | `MIRROR` | — | 自动 | 复制相邻鬼的 provides 标签 | 复制品减半 + 8 秒寿命 |
| **收容鬼** | 净化 | — | — | 自动 | 吃掉垃圾，释放缓冲 | 吃掉垃圾时自身占位 |
| **供品口** | 终端 | — | — | — | 唯一接受供物的目标 | 不可移动 |

### 7.2 后续规划（长期内容，不进 Demo）

| 鬼 | 动词 | 独特规则 | 代价 |
|---|---|---|---|
| 鼓鬼 | 搏动 | 全场鬼按节拍同时触发一次共鸣 | 消耗自身充能 |
| 溺鬼 | 渗漏 | 邻格线缆漏水，线上货物会流失 | 漏水范围随等级扩大 |
| 缚鬼 | 束缚 | 固定相邻鬼的位置，使其不能被移动 | 固定后不可再共鸣 |
| 算盘鬼 | 增值 | 给经过的货物记价，交付时供品翻倍 | 每记一次自身积攒负面状态 |
| 甲背鬼 | 搬运 | 唯一能跨越障碍传输 | 极慢，且占用大量缓冲 |

### 7.3 设计约束

- 每只鬼只能有 **一个**独特机制，机制必须能与工业化叙事自洽（长舌＝收集、镜＝复制、上吊＝吊挂）。
- 鬼总数控制在 12~15 只，靠标签组合撑起变化，而不是靠数量。
- 同一只鬼在不同邻居组合下行为不同 → 拓扑决策有深度。

## 8. 关卡与章节

**关卡内是谜题/优化题**（限时 + 目标 + 三轴评分），**关外是元进度**（只解锁新鬼）。

### 8.1 评分三轴

| 轴 | 含义 | 引导的设计 |
|---|---|---|
| 效率 | 单位时间供品产量 | 造线紧凑、少冗余 |
| 手动 | 完成所需点击次数 | 逼玩家优化共鸣组合而非硬点 |
| 空间 | 占用格数 / 可用格数 | 逼玩家做取舍而非铺满 |

三轴对应三套系统（物流 / 注意力 / 拓扑），评分表本身就是给玩家的优化指南。

星级：1★ 达标；2★ 达到基准时间；3★ 三轴同时达标。

### 8.2 章节结构（长期）

| 章 | 主题 | 新增内容 |
|---|---|---|
| 1 | 学会一条链 | 长舌鬼、灶鬼、供品口；无共鸣、无空间限制 |
| 2 | 学会共鸣 | 上吊鬼；引入手动与垃圾 |
| 3 | 学会取舍 | 收容鬼、镜鬼；残魂堆积压空间 |
| 4 | 学会拓扑 | 甲背鬼；障碍地形 |
| 5 | 综合 | 全部鬼 + 多目标 + 严限时 |

### 8.3 Demo 三关（约 5 分钟）

| 关 | 时长 | 教什么 | 引入 |
|---|---|---|---|
| 第 1 关 | ~90s | 拖放、连线、喂魂、交付 | 长舌鬼、灶鬼、供品口 |
| 第 2 关 | ~120s | 共鸣、代价、垃圾 | 上吊鬼（手动）、收容鬼 |
| 第 3 关 | ~120s | 拓扑决策、复制风险 | 镜鬼；地图变窄 |

**Demo 要证明的唯一一件事**：两只鬼贴在一起会来电，且这个电能带来有代价的选择。做不到，画再多概念图也没用。

## 9. 元进度

- **只解锁新鬼**，解锁后每关可用鬼池扩大。
- 不做纯数值加成，不做传统科技树。
- 解锁顺序即教学顺序：一关一个新概念，一次只加一个维度。
- 长期可加「关卡选择 + 星级挑战」，但不加数值成长线。

## 10. 教程系统

**形式**：对话框（角色立绘/头像 + 文字 + 继续键）+ **聚光灯遮罩**——周围变黑，中间高亮目标区域。

**实现要点**：
- 遮罩用 `CanvasLayer` + 全屏 `ColorRect`（半透明黑）+ 上方挖一个亮区。亮区可用 `Control` 的圆形遮罩（Shader 或 `Light2D` + 遮罩贴图）。
- 亮区跟随目标节点世界坐标，实时更新；目标移动时亮区跟随。
- 对话框逐条推进，玩家点击继续 → 亮区移到下一目标 → 玩家完成指定操作 → 对话框继续。
- 步骤可被跳过（设置项「已看过教程的段落不再重复」）。
- 教程内容与关卡数据绑定（放在关卡配置里，不硬编码在 UI 脚本中）。

**教学只覆盖必要**：拖放、连线、点击手动鬼、交付。

## 11. 存档

**粒度**：全局存档 + 每关进度合并在同一份存档文件内。

**存档内容**：

| 段 | 内容 |
|---|---|
| `version` | 存档版本号，用于迁移 |
| `progress` | 已解锁关卡、每关最佳星级、当前所在关 |
| `unlocked_ghosts` | 已解锁鬼列表 |
| `settings` | 音量（master / music / sfx / dialogue / ambience）、教程跳过标记、屏幕震动/特效开关 |
| `meta` | 累计游玩时长、通关次数 |

**原则**：
- 存档通过 `SignalBus` 广播变化，实体用 `ExportSaveData() -> Dictionary` / `LoadSaveData(data: Dictionary) -> void` 序列化（遵循 `src/AGENTS.md` 第四节）。
- 关卡中途退出**不保存**（关卡内状态是瞬态），只保存进度与设置。这避免存档一致性难题。
- 音量设置沿用现有 `user://audio_settings.cfg`（`Util.gd` 已实现），**不重复造**；总存档另行 `user://savegame.cfg`。
- 写入时机：解锁新鬼、关卡结算、设置变更、退出游戏（`NOTIFICATION_WM_CLOSE_REQUEST` / `_notification`）。

新增一只鬼 = 加一个 `.tres` + 一个 `.gd`，**不改核心逻辑**。这是「元进度只解锁新鬼」能长期扩展的技术前提。

### 14.3 命名与通信规范

- 公共方法 PascalCase + `##` 文档注释；内部方法 `_snake_case`。
- 常量全大写下划线，先检查 `Autoloads/` 是否已有同义常量。
- 跨实体通信**一律走 `SignalBus`**，不直接调用别的方法。
- 全部数值导出到 `ExportSettings.gd`（AGENTS.md 第八节）。
- `class_name` 只在 `Common/` 中声明通用类别。
