# 鬼工厂 · 策划案

> Godot 4.7.2 · `src/` 为工程根 · 本文是实现依据，标记〔定〕已确定 / 〔初〕初版参数 / 〔待〕待拍板

---

## 0. 一句话

> **《鬼工厂》是一款网格上的自动化建造游戏：你把「会自己运转的鬼」摆进地图，让它们互相触发、互相供养，像搭工厂流水线一样把鬼能越造越多。**

**差异点**：市面上的自动化游戏里，机器是主角、能量是消耗品。这里**鬼是规则而不是机器**——每只鬼只有一条独特机制，两只鬼贴在一起才会「共鸣」产鬼能。所以产线的效率取决于你怎么排布它们，而不是你解锁了多少科技。

---

## 1. 核心循环

```
摆鬼 → 连线 → 鬼自动运转
              ↓
        采集区掉料 → 加工 → 供品口交付（得分）
              ↓
        产能区自转产鬼能（造更多鬼）
              ↓
        限时内达标 → 星级 → 解锁新鬼
```

**玩家始终在回答一个问题**：

> 有限格子里，铺一条快而脏的产线，还是造一条长而慢的产能链？

---

## 2. 两套经济，互不依赖

〔定〕这是全局最重要的结构决策。

| | 产出 | 来源 | 瓶颈 | 用途 |
|---|---|---|---|---|
| **鬼能线** | 鬼能 | **产能区**（自持引擎） | 链长 ÷ 舌头 CD | 造鬼、造线 |
| **交付线** | 供品（计分） | 采集 → 加工 → 供品口 | 缓冲容量 | 达成关卡目标 |

产能区不产供品，交付线不产鬼能。**每一格空间都要在这两条线之间分配。**

〔定〕如果只有一条经济线，玩家只有一个优化方向，很快会腻。两条线各有独立瓶颈，才有「先扩哪边」的真取舍。

---

## 3. 地图与空间

〔定〕**地图是预先设计好的固定小网格**，含地形与障碍。玩家在既定地图里布置鬼和线，不能改变地形。

| 项 | 规则 |
|---|---|
| 节点鬼 | 占 1 格 |
| 采集鬼 | 占其采集区实际格数 |
| **线** | 每经过 1 格占 1 格，**拐角格只算一次** |

〔定〕线的占位是空间管理的核心：一条绕远的线吃掉 6 格，就少放 6 只鬼。

〔初〕空间预算逐关收紧：12 / 18 / 24 格。

## 4. 鬼

〔定〕每只鬼只有**一个**独特机制，且要与工业化叙事自洽（长舌＝收集、镜＝复制、吊死＝吊挂）。鬼总数控制在 12~15 只，靠组合撑变化。

| 鬼 | 独特机制 | 自动/手动 | 造价 | 占格 |
|---|---|---|---|---|
| **长舌鬼** | 本体固定，舌头固定一格，像 MC 活塞按 CD 伸缩 | 自动 | 6 | 1 |
| **吊死鬼** | 点一下挂上吊绳；挂上后自动荡回 | **手动**（一次开关） | 5 | 1 |
| **不倒翁鬼** | 被推动就产鬼能 | 自动 | 4 | 1 |
| **灶鬼** | 按配方转化形态，带损耗 | 自动 | 8 | 1 |
| **岔口鬼** | 一分为二，固定 1:1 | 自动 | 10 | 1 |
| **贪食鬼** | 采集区：快、暴垃圾（40%）、占格多 | 自动 | 12 | 区域 |
| **细嚼鬼** | 采集区：慢、不暴垃圾、占格少 | 自动 | 8 | 区域 |
| **收容鬼** | 吃垃圾腾缓冲 | 自动 | 5 | 1 |
| **镜鬼** | 复制邻居端口；复制品减半 + 8 s 寿命 | 自动 | — | 1 |
| **供品口** | 接受指定形态并计分 | — | 关卡预置 | 1 |
| **线** | 传输物料（也是一种鬼） | — | 每格 1 | 每格 |

〔定〕手动鬼统一为**一次性开关式**（吊死鬼点一下挂绳），不引入持续按住型——按住会让游戏变成体力活。

## 5. 产能区：推挤链

〔定〕**长舌鬼的舌头推挤链上的鬼，推力沿链连锁传递。**

```
长舌鬼 ──推──▶ 吊死鬼 ──推──▶ 不倒翁鬼 ──推──▶ 不倒翁鬼
                (中继)        产鬼能 3          产鬼能 3
```

- 舌头伸出 → 推前方一格 → 缩回时把抓住的鬼拖回一格
- 〔定〕**推拽免费**，不需要任何物料
- 〔定〕**吊死鬼自动荡回**（`HANG` 端口自作用），玩家只负责第一次挂绳

**产能公式**：

```
一次循环产出 = 链上不倒翁鬼数 × 3
产能速率     = 链上不倒翁鬼数 ÷ 舌头 CD（初 2.0 s）
```

**取舍**：

| 想更多鬼能 | 代价 |
|---|---|
| 链上多塞不倒翁鬼 | 多占格子，挤掉产线空间 |
| 缩短舌头 CD | 速率更高但节奏更密 |
| 加吊死鬼当传力者 | 多占 1 格，链条才能继续往后延 |

〔定〕**永动机是设计意图**，产能区就是玩家要造的东西。限流靠 CD 和空间预算，不靠停止它。

## 6. 共鸣系统

〔定〕**新增一只鬼只写数据，不改核心逻辑。** 分三层。

### 6.1 端口（开放词表，有方向）

| 方向 | 含义 |
|---|---|
| `ACTION` | 我能作用于什么 |
| `RECEPTACLE` | 我能被什么作用 |

鬼 A 的 `ACTION` 命中邻居的 `RECEPTACLE` → 触发。一只鬼可以有多个端口、多种方向。

已用标签：`GRAB`（攫取）、`HANG`（悬挂）、`SWALLOW`（吞噬）、`FEED`（投喂）、`SPLIT`（分流）、`MIRROR`（复制）、`OFFER`（交付）。

### 6.2 反射（条件句）

`当 [事件] 发生于我 → 执行 [效果]`

事件：`MOVE`（被移动）、`ACTED_ON`（被作用）、`BUFFER_FULL` / `BUFFER_EMPTY`、`NEIGHBOR_CHANGED`、`TICK`。

效果：产鬼能、吐垃圾、加速、位移、改端口。

〔定〕**反射层是「不倒翁鬼」存在的前提**——它的规则是「我被移动 → 我产鬼能」，不需要对手鬼，纯自身状态。

### 6.3 触发：条件消耗，无冷却

〔定〕**共鸣不需要冷却**，条件本身就是门槛。

| 条件 | 含义 |
|---|---|
| `ON_ACTION_DONE` | 触发者完成一次动作（如舌头伸出一次） |
| `ON_ENTER_CELL` | 触发者移动到指定相邻格 |
| `ON_STATE` | 触发者进入某状态 |
| `COMPOSITE` | 多条件同时满足 |

机制：条件满足 → 结算 → 条件重置。

〔定〕**CD 就是限流器**：舌头每 2 s 伸一次，条件自然只满足一次。

〔定〕共鸣分两类：**自持型**（靠自身 CD，产能区）/ **物流型**（靠物料供给，加工与分流）。

### 6.4 代价（每条共鸣必须有）

| 代价 | 说明 |
|---|---|
| **空间占用** | 产能区与产线抢同一份预算（最硬的代价） |
| 产出打折 | 共鸣期间 ×0.5 |
| 产生垃圾 | 产出的一部分变垃圾，堵缓冲 |
| 寿命限制 | N 秒后强制解除 |
| 占位 | 共鸣中的鬼不能再与别的鬼共鸣 |
| 反向效果 | 一增一减 |

## 7. 物流：线、缓冲、背压

〔定〕**线也是鬼**，有方向、有容量。

| 项 | 规则 |
|---|---|
| 走向 | 正交折线，不斜 |
| 方向 | 输出端口 → 输入端口，不可反向 |
| 容量 | 〔初〕每段 3 个物品 |
| 移动 | 〔定〕**离散格步进**，每 0.3 s 前进一格（不用插值） |

〔定〕不用连续插值，是因为整个游戏是「一次一次像机关」的节奏，插值与网格对不齐且难做。

### 背压连锁

〔定〕缓冲满会自动向上游传播阻塞，**不需要玩家干预**：

```
输出缓冲满 → 停止收上游 → 输入缓冲满 → 停止从上线取货
→ 线满(3) → 上游鬼输出缓冲满 → 继续往上游传 → 采集区吸不走料，掉落物堆积
```

玩家的应对：重排布局、减少上游供给、或加收容鬼清垃圾。

〔初〕缓冲容量：采集鬼输出 3 / 灶鬼 3:3 / 岔口鬼 3:3 / 供品口输入 6 / 长舌鬼输出 2。

### 掉落物与垃圾

〔定〕两者都是**真实实体**，占据格子。**数值上均无上限**，不会因为太多而卡死。

〔定〕**视觉上限 = 表现层堆叠压缩**：同格最多画 5 个图标，超出转 `×N` 角标，底层数值完全准确。

〔初〕玩家必须能看出哪里堵了：缓冲满 → 鬼身脉冲警示；线满 → 物品变红；采集区堆积 → 堆叠变高。

## 8. 采集系统

〔定〕采集区**形状自由**，玩家可拖出任意形状。**形状和面积是两个独立决策**：

| | 影响 |
|---|---|
| 形状 | 掉落点覆盖到哪 |
| 面积 | 总掉落量 |

〔初〕总掉落率 = `base_rate × area^0.5`（边际递减，**不是越大越好**）。

| 面积 | 4 格 | 9 格 | 16 格 |
|---|---|---|---|
| 总率（base 0.5） | 1.0/s | 1.5/s | 2.0/s |
| 每格效率 | 0.25 | 0.167 | 0.125 |

〔定〕**形状对总量无影响**——否则自由形状就只是绘制自由，没有决策价值。

〔定〕两种触发源：采集鬼走时间轮询；节点鬼走动作触发（完成一次动作掉一个料）。

## 9. 资源与形态

〔定〕**全局只有鬼能一种硬货币**。物品按关卡定义的「形态」流转。

| 概念 | 说明 |
|---|---|
| **形态 (Form)** | 物品类别标签，全局词表、关卡引用 |
| **配方 (Recipe)** | 形态→形态的转换，**只能由配方决定** |
| **供品口** | 接受指定形态并计分 |

〔定〕**每一关的形态、配方、交付物、地图都不同**，全是关卡级数据。

〔定〕**加工带损耗**（初 0.8），差额变垃圾。垃圾因此是全系统效率的残渣，堵缓冲 → 背压 → 逼玩家重排。UI 必须显示「输入 5 / 产出 4 / 损耗 1」。

〔定〕**形态分流**：第 3 关起两个供品口收不同形态，必须用岔口鬼拆成两条支路。岔口比例**固定 1:1**，改变形态靠支路上放加工鬼。

## 10. 建造与编辑

| 操作 | 规则 |
|---|---|
| 放鬼 | 从底部牌栏拖到地图。校验：格子可用 / 不重叠 / 鬼能够 / 空间够。失败给明确反馈 |
| 连线 | 从输出端口拖到输入端口。〔初〕点源端口 → 点目标端口，系统自动生成 L 形路径；空间不够则拒绝 |
| 拆除 | 点鬼拆除，释放占格。〔初〕全额退还鬼能 |
| 移动 | 〔定〕仅暂停时可移动，运行中不可拖动 |

〔初〕拆除全额退款是为了鼓励试错重排——这是拓扑玩法的乐趣来源，扣押金会让玩家不敢动。

〔待〕**建造时游戏是否运行**：继续运行（紧张）还是自动暂停（从容）。〔初〕倾向继续 + 「规划模式」快捷键临时暂停并自由移动。

## 11. 运行循环

〔定〕逻辑与渲染分离，逻辑固定 20 Hz。

```
1. 采集掉落    采集区按轮询率生成掉落物
2. 鬼动作      推进 CD 到期的鬼（舌头伸缩、吞吐、分流）
3. 位移结算    推挤链的连锁位移，逐个结算 MOVE 反射
4. 共鸣判定    端口匹配 + 条件检查，结算共鸣与代价
5. 物流推进    物品步进一格，背压自上游向下游传播
6. 加工/交付   加工转化（计损耗）、供品口接收计分
7. 缓冲/垃圾   BUFFER_FULL 等触发反射（收容鬼吃垃圾）
8. UI 刷新     资源条、警示、倒计时
```

〔定〕顺序不可交换：先动作后位移（舌头推人产生位移），先位移后共鸣（位移触发反射），先共鸣后物流。

〔定〕**暂停条件**：打开设置 / 教程对话框显示 / 规划模式。暂停保留全部状态。

〔定〕**失败不惩罚**——关卡内不存档、局外只有解锁表，惩罚无处安放；压力只来自「时间不够」。

## 12. 关卡与元进度

### 12.1 难度按概念递增，不按数值递增

| 章 | 新增概念 |
|---|---|
| 1 | 放置、连线、吞吐、交付 |
| 2 | 形态、配方、损耗、垃圾、背压 |
| 3 | 产能区、推挤链、空间取舍 |
| 4 | 岔口鬼、镜鬼 |
| 5 | 多目标、严限时、窄地形 |

### 12.2 Demo 三关（约 5 分钟）

| 关 | 时长 | 教什么 | 引入 |
|---|---|---|---|
| 1 | 90 s | 纯输送：拖放、连线、自动运转、交付 | 长舌鬼、供品口 |
| 2 | 120 s | 加工：形态转换、损耗、垃圾、背压 | 灶鬼、贪食鬼、收容鬼 |
| 3 | 120 s | 产能区 + 形态分流 | 岔口鬼、吊死鬼、不倒翁鬼 |

### 12.3 评分三轴

| 轴 | 含义 | 引导 |
|---|---|---|
| 效率 | 单位时间交付量 | 造线紧凑 |
| 手动 | 所需点击次数 | 优化组合而非硬点 |
| 空间 | 占用格数 / 可用格数 | 做取舍而非铺满 |

1★ 达标 / 2★ 基准时间 / 3★ 三轴同时达标。

### 12.4 元进度

〔定〕**局外层 = 解锁表，每关通过后自动解锁下一项。无货币、无攒点。**

解锁新鬼 / 新形态 / 新配方 / 新机制。〔定〕关卡必须声明**可用鬼池白名单**，防止解锁的鬼带来超纲配方。

〔定〕**不做局外货币**——它会引入「这局多刷点」的元游戏，与产线专注度冲突。

### 12.5 关卡数据结构

```
Data/Levels/Level01.tres
  forms_used: [Raw]           recipes_in_use: []
  terminals: [{accepts: Raw, position: (9,5), score: 1}]
  fields:    [{shape: [...], drops: Raw, interval: 1.0, garbage_rate: 0.4}]
  obstacles: [...]            space_budget: 12
  time_limit: 90              goal_score: 20
  available_ghosts: [LongTongue, Terminal]
```

〔定〕**新增关卡 = 加一个 .tres，零代码改动。**

## 13. 教程、存档、设置

### 13.1 教程

〔定〕**对话框 + 聚光灯遮罩**（周围变黑，中间标亮目标）。

- `CanvasLayer` + 全屏半透明黑 `ColorRect` + 挖亮区（Shader 或 `Light2D`）
- 亮区跟随目标世界坐标实时更新
- 流程：点继续 → 亮区移到下一目标 → 完成操作 → 对话框继续
- 内容与关卡数据绑定，不硬编码在 UI 脚本里
- 教程期间游戏暂停

只教必要四件事：拖放、连线、点手动鬼、交付。

### 13.2 存档

〔定〕**完整存档**，`user://savegame.cfg`。

```
version / progress（已解锁关卡、最佳星级、当前关）
unlocked_ghosts / unlocked_forms / unlocked_recipes
settings（音量、教程跳过、震动、画质）/ meta（时长、通关次数）
```

- 实体用 `ExportSaveData() -> Dictionary` / `LoadSaveData(data) -> void` 序列化
- **关卡中途退出不保存**（关卡内状态是瞬态），只存进度与设置
- 音量设置沿用现有 `user://audio_settings.cfg`（`Util.gd` 已实现），**不重复造**
- 写入时机：解锁新鬼 / 关卡结算 / 设置变更 / 退出游戏

### 13.3 音频与设置

〔定〕音频总线已配：`Master / Music / SFX / Dialogue / Ambience`。

设置面板：五个音量滑条（实时生效 + 持久化，复用 `Util.SetAudioVolume/GetAudioVolume`）、跳过教程、震动开关、画质、重置进度。

> 美术与音乐风格暂缺。需要的音频类别：BGM（主菜单/关卡）、SFX（放置/连线/吞吐/共鸣/推挤/交付/失败）、UI、Dialogue。
