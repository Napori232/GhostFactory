## 1. 世界观

主角在原本的世界里一直打工，最后猝死了。

死后他发现自己家在阴间有一间工厂——美美当资本家。

要当资本家就得有人替他干活，所以他雇了一个假小子秘书鬼当左膀右臂，同时兼任新人引导。

---

## 2. 游戏概述

### 2.1 一句话

网格上的自动化建造游戏：把会自己运转的鬼摆进地图，让它们互相触发、互相供养，像搭工厂流水线一样把鬼能越造越多。

### 2.2 核心特色

市面上的自动化游戏（《沙金工业》《异星工厂》）里，机器是主角、能量是消耗品，配方解锁就是全部成长。

本作的差异：

- **鬼是规则，不是机器。** 每只鬼只有一条独特机制。
- **两只产能鬼贴在一起才会「共鸣」产鬼能。** 产线效率取决于怎么排布它们，而不是解锁了多少配方。
-**鬼本质上分成运输，收集，产能，加工四大类，对应工业化中的流程
	
### 2.3 目标体验

- 前 30 秒：看懂「摆鬼 → 连线 → 它自己动」
- 前 2 分钟：发现两只鬼贴一起会来电
- 一整局：不断在「造引擎」和「造产线」之间分配有限的空间

---

## 3. 核心玩法

### 3.1 玩法循环

```
摆鬼 → 连线 → 鬼自动运转
              ↓
        产能区掉料 → 加工 → 供品口交付（计分）
              ↓
        产能区自转产鬼能（造更多鬼）
              ↓
        限时内达标 → 结算星级 → 解锁新鬼
```

### 3.2 玩家操作

| 操作 | 输入 | 说明 |
|---|---|---|
| 放置鬼 | 从底部鬼牌栏拖到地图 | 拖动放置 |
| 连线 | 从鬼的输出端口拖到输入端口 | 〔初〕点源端口 → 点目标端口，系统自动生成 L 形路径 |
| 触发手动鬼 | 点击该鬼 | 吊死鬼：点一下挂上吊绳 |
| 拆除 | 点击鬼或线段 | 释放占格 |
| 移动鬼 | 拖动 | 仅暂停时可拖，运行中不可 |

### 3.3 胜负条件

- **目标**：限时内交付达到 `goal_score` 份供品
- **失败**：倒计时归零且未达标，可重试，不扣任何东西
- **结算**：三轴评分（效率 / 手动 / 空间）→ 1~3 星 → 解锁新鬼

## 4. 鬼的通用规则

### 4.1 设计原则

- 每只鬼只有 **一个** 独特机制，且要与工业化叙事自洽
- 鬼总数控制在 12~15 只，靠组合撑变化而不是靠数量
- **每只鬼只描述「我自己做什么」，不描述「我和谁在一起会怎样」**——后者由物理层涌现，见 §5
- **本版不引入鬼的升级。** 成长只通过解锁新鬼和新机制，不做数值成长。

### 4.2 几何占位

每只鬼在地图上占据若干网格格，占位是**几何形状**（可以是 L 形、T 形、多格不规则），不是固定格子数。占位形状属于鬼自身的数据，随放置一起对齐。

采集鬼的占位范围由玩家放置后框定，不是固定形状。

具体形状见 `Docs/Ghosts.md` §2。

### 4.3 手动鬼

手动鬼统一为**一次性开关式**（点一下切换状态），不引入持续按住型——按住会让游戏变成体力活。

### 4.4 鬼的类别

按工业化流程，鬼天然分四类：运输、收集、产能、加工（供品口另计为交付）。

**类别是描述性标签，不参与任何判定逻辑。** 它只用于两件事：给玩家读懂这只鬼是干什么的；给关卡设计选教学点。两只运输鬼连上不会触发「运输加成」，两只加工鬼连上也不会——它们只是各自按自己的规则跑，结果恰好落在分类描述的倾向里。

各类鬼的默认行为倾向与典型成员见 `Docs/Ghosts.md` §1。

## 5. 物理层：共振的涌现

### 5.1 核心认知：没有「共鸣规则」这回事

**共鸣不是一条需要被写下来的规则，而是物理层自动叠加后的自然结果。**

参考 Minecraft 的红石电路：红石块的逻辑只有「有电 / 没电」，中继器只有「充能 / 断电」，比较器只有「比较两个信号」——**没有任何一条规则写着「红石块 + 中继器 + 比较器 = 一个永动机」**。但你把这三个方块按正确的位置摆好，它就是个永动机。规则没变，涌现变了。

鬼工厂同理：

| 你以为的写法 | 实际该有的写法 |
|---|---|
| 长舌鬼 + 吊死鬼 = 永动机 | 长舌鬼会自动拉取，吊死鬼会自动伸展，两者相邻且连上时，行为自然叠加 |
| 两只贪食鬼相邻 = 采集加速 | 两只贪食鬼各自按自己的面积与基率采集，区域重叠处自然各采各的 |
| 不倒翁鬼被推动 = 产鬼能 | 不倒翁鬼的规则只有「我被移动 → 我产鬼能」，谁来推都一样 |

**推论：鬼的行为只描述「我自己做什么」，不描述「我和谁在一起会怎样」。** 后者是玩家的发现，不是程序员的分支。

所以本节不设「共鸣规则表」。取而代之的是三样东西：

1. **鬼的自主行为** —— 每只鬼自己就会做的事（长舌鬼自己会拉取，吊死鬼自己会伸展）
2. **标签** —— 只用来检验「能不能联动」，不决定「联动出什么」
3. **物理求解** —— 每 tick 统一结算所有鬼的意图与冲突

### 5.2 标签的唯一职责：合法性检查

端口标签（`ACTION` / `RECEPTACLE`）**只回答一个问题：这两个鬼之间允许建立物理连接吗？**

```
长舌鬼.ACTION = GRAB      （长舌鬼能作用于「被抓住的东西」）
吊死鬼.RECEPTACLE = GRAB   （吊死鬼能被抓住）
→ 标签命中，允许连接
```

标签**不回答**「连上以后会发生什么」。那是物理层自己算出来的。

已用标签：`GRAB` 攫取 / `HANG` 悬挂 / `SWALLOW` 吞噬 / `FEED` 投喂 / `SPLIT` 分流 / `MIRROR` 复制 / `OFFER` 交付。

| 标签 | 谁发布 | 谁接受 | 物理含义 |
|---|---|---|---|
| `GRAB` | 长舌鬼 | 吊死鬼 | 舌头抓取力可以作用在吊绳上 |
| `HANG` | 吊死鬼 | 长舌鬼 | 吊绳可以挂住舌头 |
| `SWALLOW` | 灶鬼 | 长舌鬼 | 吞料口可以被喂 |
| `FEED` | 灶鬼 | 长舌鬼 | 投喂 |
| `SPLIT` | 岔口鬼 | 长舌鬼 | 分流 |
| `SPIT` | 贪食鬼 / 细嚼鬼 | 灶鬼 | 喷吐的料可以进吞噬口 |
| `MIRROR` | 镜鬼 | 任意 | 复制对方的端口 |
| `OFFER` | — | 供品口 | 供品口只接受交付 |

**校验时机**：玩家连线时立刻检查并给出反馈（线变红＝标签不匹配）。连上之后标签就不再参与了。

### 5.3 物理层：意图与结算

每只鬼每 tick 产生一个**意图**（Intent），描述「我想做什么」。所有意图收集完毕后统一结算，解决冲突。

意图类型：

| 意图 | 产生者 | 含义 |
|---|---|---|
| `PULL` | 长舌鬼 | 抓住相邻格的目标，拉向自己 |
| `EXTEND` | 吊死鬼 | 向目标方向伸展一格 |
| `RETRACT` | 吊死鬼 | 收回伸展 |
| `PUSH` | 长舌鬼（缩回时） | 把抓住的目标推出去 |
| `SWAY` | 不倒翁鬼 | 被推动时的回摆反应 |
| `CONSUME` | 灶鬼 / 收容鬼 | 从输入缓冲取一件物料 |
| `PRODUCE` | 灶鬼 / 不倒翁鬼 / 贪食鬼 | 产出物料或鬼能 |
| `COLLECT` | 贪食鬼 / 细嚼鬼 | 从采集区取一件掉落物 |
| `TRANSFER` | 任意 | 沿连线送一件物料 |

结算规则（每 tick，一次性跑完）：

1. **收集意图**：所有鬼同时提出意图，互不知情
2. **合法性过滤**：意图涉及的连接若标签不匹配，该意图作废
3. **冲突消解**：同一目标被多只鬼争抢时，按下列优先级裁决
   - 优先级 = 鬼的 `priority` 字段，高者胜
   - 同优先级则按格子距离近者胜，再相同则按放置顺序（先放的胜）
4. **执行**：胜出的意图执行，其余作废
5. **连锁**：执行产生的新状态可能触发下一 tick 的意图

**关键：第 3 步的优先级裁决是唯一的「仲裁规则」。** 所有「两只鬼相邻会怎样」的答案，都从这里长出来，不需要额外写规则。

### 5.4 涌现案例：三个玩家自己会发现的机关

#### 案例一 · 永动机（长舌鬼 + 吊死鬼）

```
长舌鬼        吊死鬼
[本体][舌头]——[吊绳]
   ↓ 自动拉取     ↓ 自动伸展
```

- 长舌鬼的舌头自动伸出，试图抓住相邻格的目标（`GRAB`）
- 吊死鬼的 `RECEPTACLE = GRAB`，所以它可以被抓住
- 吊死鬼挂上后自动伸展，伸展方向顶住长舌鬼的舌头
- 长舌鬼缩回时把吊死鬼拉近，吊死鬼伸展时又把长舌鬼顶远
- **两者来回推拉，永不停歇**

代码里**没有任何一行写着「长舌鬼 + 吊死鬼 = 永动机」**。只有：长舌鬼每 2.0s 尝试 PULL、吊死鬼每周期尝试 EXTEND，以及标签校验允许它们建立连接。

#### 案例二 · 产能链（长舌鬼 + 吊死鬼 + 不倒翁鬼）

```
长舌鬼 → 吊死鬼 → 不倒翁鬼 → 不倒翁鬼
（拉）    （中继）   （产鬼能）  （产鬼能）
```

长舌鬼拉吊死鬼，吊死鬼的伸展又推不倒翁鬼，不倒翁鬼的规则是「我被移动 → 我产鬼能」。

**链长不是参数，是玩家摆出来的几何结果。** 能接多长取决于摆了多少只、占位接不接得上、空间预算还剩多少。

#### 案例三 · 采集竞争（两只贪食鬼）

两只贪食鬼框定的采集区如果重叠，同一格的掉落物被两只鬼抢——**由 §5.3 的优先级裁决决定谁拿到**。玩家因此学会把采集区分开，或者故意让它们重叠来抢高价值区。

### 5.5 四大类鬼：分类只描述「默认行为倾向」

按工业化流程，鬼天然分成四类。**分类不是共鸣规则，而是「这只鬼默认在流程里扮演什么角色」的说明。**

| 类别 | 工业化对应 | 默认行为 | 典型鬼 | 共鸣倾向 |
|---|---|---|---|---|
| **运输** | 搬运 | 把东西从一处送到另一处 | 长舌鬼、线鬼、岔口鬼 | 与运输鬼联动 → 链路加长，吞吐叠加 |
| **收集** | 采集 | 从场域获取原料 | 贪食鬼、细嚼鬼 | 与收集鬼联动 → 竞争同一片区，或分区互补 |
| **产能** | 产出 | 凭空产出鬼能 | 不倒翁鬼 | 与运输鬼联动 → 被推动才产，推力链决定产能 |
| **加工** | 转化 | 改变物料形态 | 灶鬼、镜鬼、收容鬼 | 与加工鬼联动 → 形态接力（Raw→Processed→成品） |

**分类的真正用途有两个：**

1. **给玩家读懂** —— 拿到一只新鬼，看类别就知道它是干什么的
2. **给关卡设计用** —— 「这一关要教运输链」就选运输类，「这一关要教损耗」就选加工类

**分类不参与任何判定逻辑。** 两只运输鬼连上不会触发「运输共鸣」加成，两只加工鬼连上也不会。它们只是各自按自己的规则跑，结果恰好落在分类描述的倾向里。

`GhostData.category` 字段就存这个分类，值域：`transport` / `collect` / `produce` / `process` / `deliver`（供品口）。

### 5.6 代价

代价不是「共鸣的附加惩罚」，而是**物理约束的必然结果**——空间、材料、时间不够时，机关就是转不动。

| 代价 | 物理来源 |
|---|---|
| 空间占用 | 推力链与产线抢同一份空间预算 |
| 产出打折 | 加工的 yield < 1，差额变成垃圾 |
| 产生垃圾 | 损耗与采集区的垃圾率，堵住缓冲 |
| 背压 | 缓冲与线的容量有限，满了就停 |
| 寿命限制 | 镜鬼复制品 8 秒后消失 |
| 优先级劣势 | 同目标争抢时优先级低的鬼空转 |
| 反弹 | 鬼被推挤时会推挤别人（案例一） |

具体数值见 `Docs/Ghosts.md` §3。

## 6. 产能区

### 6.1 推挤链

长舌鬼的舌头推挤链上的鬼，推力沿链连锁传递。

```
长舌鬼 ──推──▶ 吊死鬼 ──推──▶ 不倒翁鬼 ──推──▶ 不倒翁鬼
              (中继)        产鬼能              产鬼能
```

- 舌头伸出 → 推前方一格 → 缩回时把抓住的鬼拖回一格
- 推拽免费，不需要任何物料
- 吊死鬼自动荡回（`HANG` 端口自作用），玩家只负责第一次挂绳

**这条链不是一条被写下的规则**，而是三只鬼各自的自主行为叠加的结果——详见 §5.4 案例二。

### 6.2 产能公式

```
一次循环产出 = 链上不倒翁鬼数 × 单只产量
产能速率     = 链上不倒翁鬼数 ÷ 舌头 CD
```

数值见 `Docs/Ghosts.md` §3。

### 6.3 链的长度

**链长不是一个独立参数，而是机关功能嵌套出来的结果。**

每只鬼本身是一个机关（长舌鬼＝推力源，吊死鬼＝回位中继，不倒翁鬼＝产能器）。能嵌套多长取决于：

- 玩家摆了多少只鬼
- 这些鬼的几何占位能不能接得上
- 空间预算还剩多少

链能接多长就多长，接不上就断。**没有链长上限参数**，链的上限就是玩家摆得出来的长度。

### 6.4 取舍

| 想更多鬼能 | 代价 |
|---|---|
| 链上多塞不倒翁鬼 | 多占格子，挤掉产线空间 |
| 缩短舌头 CD | 速率更高但节奏更密 |
| 加吊死鬼当传力者 | 多占 1 格，链条才能继续往后延 |

## 7. 物流系统

### 7.1 线

线也是鬼，有方向、有容量。

| 项 | 规则 |
|---|---|
| 走向 | 正交折线，不斜 |
| 方向 | 输出端口 → 输入端口，不可反向 |
| 容量 | 每段有限，见 §15 |
| 移动 | 离散格步进，不用插值 |

不用连续插值是因为整个游戏是「一次一次像机关」的节奏，插值与网格对不齐。

### 7.2 缓冲与背压

每只鬼有输入缓冲与输出缓冲，容量按鬼不同（见 `Docs/Ghosts.md` §1）。

背压连锁（自动发生，不需要玩家干预）：

```
输出缓冲满 → 停止收上游 → 输入缓冲满 → 停止从上线取货
→ 线满 → 上游鬼输出缓冲满 → 继续往上游传 → 采集区吸不走料，掉落物堆积
```

玩家应对：重排布局、减少上游供给、或加收容鬼清垃圾。

### 7.3 掉落物与垃圾

两者都是**真实实体**，占据格子。数值上**均无上限**，不会因为太多而卡死。

视觉上限只是表现层的堆叠压缩：同格最多画 5 个图标，超出转 `×N` 角标，底层数值完全准确。

玩家必须能看出哪里堵了：

| 信号 | 表现 |
|---|---|
| 缓冲满 | 鬼身脉冲警示 |
| 线满 | 线段上物品变红闪烁 |
| 采集区堆积 | 堆叠高度上升 |

### 7.4 供品口

**供品口没有速率上限**，来多少收多少。

节流靠关卡设计实现：目标量、限时、空间预算、掉落速率共同决定一关能交付多少。供品口本身不做任何限速或计分衰减。

## 8. 采集系统

### 8.1 采集鬼

采集区本身是一只鬼，玩家实际把它放到地图上，然后拖动框定它覆盖的范围。

| | 效果 |
|---|---|
| 形状（框定的范围） | 掉落点覆盖到哪 |
| 面积 | 总掉落量 |

总掉落率 = `base_rate × area^e`，e < 1（边际递减，不是越大越好）。数值见 `Docs/Ghosts.md` §3。

**形状对总量无影响**——否则自由形状只是绘制自由，没有决策价值。

### 8.2 掉落触发

| 触发源 | 用于 | 效果 |
|---|---|---|
| 时间轮询 | 采集鬼 | 范围内随机位置掉一个料 |
| 动作触发 | 节点鬼 | 完成一次有效动作掉一个料 |

## 9. 资源与形态

### 9.1 鬼能

全局唯一的硬货币，用于建造鬼与线。来源只有产能区。

### 9.2 形态

物品按关卡定义的形态流转。每一关的形态、配方、交付物、地图都不同，全是关卡级数据。

| 概念 | 说明 |
|---|---|
| 形态 Form | 物品类别标签，全局词表、关卡引用 |
| 配方 Recipe | 形态→形态的转换，只能由配方决定 |
| 供品口 | 接受指定形态并计分 |

### 9.3 加工与损耗

加工带损耗，差额变垃圾。数值见 `Docs/Ghosts.md` §3。

垃圾因此是全系统效率的残渣：堵缓冲 → 背压 → 逼玩家重排。

UI 必须显示「输入 5 / 产出 4 / 损耗 1」。

### 9.4 形态分流

岔口鬼比例固定 1:1，不可调。改变某条支路的形态靠在该支路上放加工鬼。

```
          ┌→ 供品口 A（收 Raw）
料源 → 岔口 ┤
          └→ 供品口 B（收 Processed，经加工鬼转换）
```

## 10. 地图与空间

### 10.1 地图

地图是预先设计好的固定小网格，含地形与障碍。玩家在既定地图里布置鬼和线，不能改变地形。尺寸逐关设计时定。

### 10.2 空间预算

| 项 | 规则 |
|---|---|
| 节点鬼 | 按其几何占位形状占据的格子数 |
| 采集鬼 | 按框定范围占据的格子数 |
| 线 | 每经过 1 格占 1 格，拐角格只算一次 |

线的占位是空间管理的核心：一条绕远的线吃掉 6 格，就少放 6 只鬼。

### 10.3 两套经济

| | 产出 | 来源 | 瓶颈 | 用途 |
|---|---|---|---|---|
| 鬼能线 | 鬼能 | 产能区（自持引擎） | 链长 ÷ 舌头 CD | 造鬼、造线 |
| 交付线 | 供品（计分） | 采集 → 加工 → 供品口 | 缓冲容量、关卡限时 | 达成关卡目标 |

产能区不产供品，交付线不产鬼能。每一格空间都要在这两条线之间分配。

如果只有一条经济线，玩家只有一个优化方向，很快会腻。两条线各有独立瓶颈，才有「先扩哪边」的取舍。

## 11. 关卡

### 11.1 难度设计

难度按概念递增，不按数值递增。

| 章 | 新增概念 |
|---|---|
| 1 | 放置、连线、吞吐、交付 |
| 2 | 形态、配方、损耗、垃圾、背压 |
| 3 | 产能区、推挤链、空间取舍 |
| 4 | 岔口鬼、镜鬼 |
| 5 | 多目标、严限时、窄地形 |

### 11.2 Demo 三关

| 关 | 时长 | 教什么 | 引入 |
|---|---|---|---|
| 1 | 90s | 纯输送：拖放、连线、自动运转、交付 | 长舌鬼、供品口 |
| 2 | 120s | 加工：形态转换、损耗、垃圾、背压 | 灶鬼、贪食鬼、收容鬼 |
| 3 | 120s | 产能区 + 形态分流 | 岔口鬼、吊死鬼、不倒翁鬼 |

镜鬼与细嚼鬼挪到后续章节。

### 11.3 评分

| 轴 | 含义 | 引导 |
|---|---|---|
| 效率 | 单位时间交付量 | 造线紧凑 |
| 手动 | 所需点击次数 | 优化组合而非硬点 |
| 空间 | 占用格数 / 可用格数 | 做取舍而非铺满 |

1★ 达标 / 2★ 基准时间 / 3★ 三轴同时达标。

### 11.4 关卡数据结构

```
Data/Levels/Level01.tres
  forms_used: [Raw]           recipes_in_use: []
  terminals: [{accepts: Raw, position: (9,5), score: 1}]
  fields:    [{shape: [...], drops: Raw, interval: 1.0, garbage_rate: 0.4}]
  obstacles: [...]            space_budget: 12
  time_limit: 90              goal_score: 20
  available_ghosts: [LongTongue, Terminal]
```

新增关卡 = 加一个 .tres，零代码改动。

### 11.5 元进度

局外层是解锁表，每关通过后自动解锁下一项。无货币、无攒点。

| 解锁项 | 作用 | 何时 |
|---|---|---|
| 新鬼 | 可放置的新规则单元 | 主体 |
| 新形态 | 关卡可用的物品形态 | 第 2 关 |
| 新配方 | 形态转换规则 | 第 2 关 |
| 新机制 | 如槽位可解锁、线可升级 | 后期 |

关卡必须声明可用鬼池白名单，防止解锁的鬼带来超纲配方。

不做局外货币——它会引入「这局多刷点」的元游戏，与产线专注度冲突。

## 12. 教程

### 12.1 形式

秘书鬼的对话框 + 聚光灯遮罩（周围变黑，中间标亮目标）。

- `CanvasLayer` + 全屏半透明黑 `ColorRect` + 挖亮区（Shader 或 `Light2D`）
- 亮区跟随目标世界坐标实时更新
- 流程：点继续 → 亮区移到下一目标 → 完成操作 → 对话框继续
- 内容与关卡数据绑定，不硬编码在 UI 脚本里
- 教程期间游戏暂停

### 12.2 教学范围

只教四件事：拖放、连线、点手动鬼、交付。

〔初〕第 1 关结尾留一个 5 秒的互动信号（位移反射闪一下 + 鬼能 +3 + 一句秘书鬼的吐槽），让玩家第一次看到两只鬼互动。

### 12.3 秘书鬼

- 定位：主角的秘书兼左膀右臂，新人引导者
- 性格：假小子，嘴硬爱吐槽，但干活利落
- 台词方向：毒舌不刻薄，讲效率讲规矩，不卖萌
- 功能：教程发言人，兼后期的剧情提示

### 16.1 目录

```

│   ├── SignalBus.gd        # 资源/关卡/板面信号

│   └── Util.gd             # 复用音频与定时器
├── Common/
│   ├── GhostTag.gd         # 端口标签常量与配对校验
│   ├── GhostData.gd        # 鬼数据结构（类别、占位、端口、优先级）
│   ├── FormData.gd         # 形态数据结构
│   ├── RecipeData.gd       # 配方数据结构
│   ├── LevelData.gd        # 关卡数据结构
│   ├── GridUtil.gd         # 网格坐标、邻接、几何占位计算
│   ├── UIPalette.gd        # UI 12 色板
│   ├── UIEffects.gd        # UI 动效库
│   └── ResourceUtil.gd     # 资源属性读取

    └── StartMenu/  # 主菜单

Data/
├── Forms/  Recipes/  Ghosts/  Levels/  Tutorial/   （全部 .tres）
```

**新增一只鬼 = 一个 .tres + 一个行为方法，不改核心逻辑。** 核心层没有「鬼 A 和鬼 B」这种分支，只有「意图 → 统一结算」。

### 16.2 信号

新增到 SignalBus：

```
GhostPlaced / GhostRemoved / GhostDisplaced
GhostActionDone / ResourceChanged / FormChanged / BufferStateChanged
LevelStarted / LevelCompleted / LevelFailed / GhostUnlocked
TutorialStepChanged / SaveGameWritten
SpiritChanged / DeliveredChanged / ItemDelivered / LineCreated
```

**没有 `ResonanceTriggered`。** 因为共鸣不是一次触发，而是一个持续状态——鬼一直连着就一直生效。

### 16.3 运行循环

逻辑与渲染分离，逻辑固定 20 Hz。**每 tick 是一次「收集意图 → 统一结算」，不是「逐只鬼跑 if 分支」**：

```
1. 采集掉落    采集区按轮询率生成掉落物到具体格子
2. 提出意图    每只鬼按自己的 CD 与状态提出本 tick 的意图
                （长舌鬼 PULL、吊死鬼 EXTEND、不倒翁鬼 SWAY、
                  灶鬼 CONSUME、贪食鬼 COLLECT、线鬼 TRANSFER…）
3. 合法性过滤  意图涉及的连接若端口标签不匹配，该意图作废
4. 冲突消解    同一目标被多只鬼争抢时按 priority → 距离 → 放置顺序裁决
5. 执行        胜出的意图执行，其余作废
6. 物流推进    物料沿连线步进一格，背压自上游向下游传播
7. 缓冲/垃圾   缓冲满触发垃圾堆积与停机
8. UI 刷新     资源条、警示、倒计时
```

**关键：第 2 步里没有「如果 A 和 B 相邻就怎样」的分支。** 每只鬼只产出自己的意图，谁赢由第 4 步统一裁决。所有「两只鬼凑一起会怎样」都是这三步叠出来的结果，见 §5。

顺序不可交换：先采集后动作（鬼才有料可拿），先意图后位移（位移是意图的结果），先位移后物流（物料要等鬼动完才走）。

暂停条件：打开设置 / 教程对话框显示 / 规划模式（按住快捷键临时暂停并自由移动鬼）。暂停保留全部状态。

### 16.4 规范

遵循 `src/AGENTS.md`：

- 公共方法 PascalCase + `##` 文档注释，内部方法 `_snake_case`
- 跨实体通信一律走 SignalBus，不直接调用别的方法
- 数值全部导出到 `ExportSettings.gd`
- `class_name` 只在 `Common/` 声明
