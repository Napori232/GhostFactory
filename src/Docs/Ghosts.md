# 机关总表

> 每只机关只描述**「我自己做什么」**，不描述「我和谁在一起会怎样」。
> 后者是物理层叠加的结果，见 `GameDesign.md` §8。
> 「类型」一列是给玩家读懂与关卡设计用的，不参与任何判定逻辑。
> 数值见 §3；关卡内具体摆放见 `Docs/LevelDesign.md`。

| 机关 | 类型 | 触发类型 | 可动性 | 自主行为（物理规则） | 输入端口 | 输出端口 | 手动 | 造价 | 占位 |
|---|---|---|---|---|---|---|---|---|---|
| **生产鬼** | 生产 | 自动 | 刚体 | 每 `cycle` 秒凭空产出 1 单位鬼能，掉在自身四邻的随机空格；四邻无空格则进入输出缓冲，缓冲满则故障 | 0 | 0 | | 5 | 1 格 |
| **采集鬼** | 采集 | 自动 | 柔体 | 在框选范围内按 DFS 一格一格搜索，走到掉落物所在格则拾取进输出缓冲；区内无掉落物则空跑 | 0 | 1 | | 8 | 1 格本体 + 搜索区（≤ 9 格） |
| **运输鬼** | 运输 | 自动 | 柔体 | 沿已连路径把输出缓冲里的一件东西搬到下一台机器的输入端口；目标缓冲满则停在原地等待 | 1 | 1 | | 6 | 1 格 |
| **处理鬼** | 处理 | 自动 | 刚体 | 从输入缓冲取 1 件鬼能，`process_time` 秒后产出 1 份贡品，同时按 25% 损耗产出 1 件杂质（落地占格）；输入取的是杂质则改为再处理，产出回收鬼能且不再产杂质 | 1 | 1 | | 12 | 2 格（2×1） |

## 2. 几何占位

每只机关在地图上占据若干网格格，占位是**几何形状**，形状由设计与机关种类决定，占格总数是形状面积（不是「格数决定形状」）。

| 机关 | 占位形状 | 备注 |
|---|---|---|
| 生产鬼 | 1 格 | 简化起见先跑通单格流程 |
| 采集鬼 | 1 格本体（搜索区另计，不占格） | 搜索区是行为范围，不是占位 |
| 运输鬼 | 1 格 | |
| 处理鬼 | 2 格（2×1） | 输入口与输出口各在一端 |
| 守财鬼 | 1 格 | |
| 吊死鬼 | 1 格 | |
| 推舌鬼 | 1 本体 + 1 舌头附属 | 舌头附属格随朝向变化 |
| 贪食鬼 | 1 格 | |

〔待〕各机关的具体形状（直线 / L 形 / T 形 / 多格不规则）尚未逐只确定。

## 4. 状态与故障

四种状态与点击切换规则见 `GameDesign.md` §4.5。逐机关的故障判定：

| 机关 | 故障条件 | 恢复 |
|---|---|---|
| 生产鬼 | 四邻无空格且输出缓冲满 | 玩家点击 → 待机 |
| 采集鬼 | 搜索区被掉落物完全堵死，或输出缓冲满且下游满 | 玩家点击 → 待机 |
| 运输鬼 | 目标缓冲长期满（下游堵塞） | 玩家点击 → 待机 |
| 处理鬼 | 缺料等待超时 | 玩家点击 → 待机 |

**故障不等于报废。** 故障的机关仍在占格、仍在缓冲里存着东西，修好后原地恢复。

## 5. 涌现出来的机关（不是规则）

以下全部是**物理层自动叠加的结果**，代码里没有对应的特判。每条只写「哪几只机关 + 怎么摆」。

| 机关 | 怎么摆 | 为什么成立 |
|---|---|---|
| **永动机** | 推舌鬼的舌头连上吊死鬼 | 推舌鬼自动拉取，吊死鬼自动伸展，两者互推互拉形成往复 |
| **推动链** | 推舌鬼 → 吊死鬼 → 守财鬼 → 守财鬼 | 推力沿链传递，链上每只守财鬼被推动即掉落鬼能 |
| **链上产线** | 推动链末端接运输鬼 | 被推动的机关带着自己缓冲里的东西一起动 |
| **双通道采集** | 采集鬼输出同时接仓库口与处理鬼 | 一次拾取，两种去处——但一件只能选一条 |
| **背压** | 供给大于下游吸收 | 缓冲与线路容量有限，满了自然停 |
| **柔体让位** | 柔体机关挤在刚体之间 | 柔体会被挤开，刚体不动——布局要留出余量 |
| **随机搜索空跑** | 搜索区大、掉落区小 | DFS 逐格遍历，找不到就白走 |

**代价不是附加惩罚**，而是物理约束的必然结果：空间不够、材料不够、缓冲满了、被抢走了——机关就是转不动。代价类型见 `GameDesign.md` §8.4。

## 6. 长期规划机关（不进 Demo）

| 机关 | 类型 | 独特机制 | 代价 |
|---|---|---|---|
| 鼓鬼 | 生产 | 全场机关按节拍同时触发一次动作 | 消耗自身充能 |
| 溺鬼 | 运输 | 邻格线缆漏水，线上物品会流失 | 漏水范围随等级扩大 |
| 缚鬼 | 运输 | 固定相邻机关的位置使其不能被移动 | 固定后不可再被推挤 |
| 镜鬼 | 感知 | 复制相邻机关的端口 | 复制品产出减半、8s 后消失 |
| 甲背鬼 | 运输 | 唯一能跨越障碍传输 | 极慢，占用大量缓冲 |
| 秤鬼 | 感知 | 比较两路缓冲里的物品数量 | 需要两条独立输入 |

## 7. 已作废的旧鬼（v8/v9 设定，不得复活）

| 旧鬼 | 作废原因 |
|---|---|
| 灶鬼 | v10 中由「处理鬼」承担加工职能 |
| 岔口鬼 | 分流改由物理挤压与多目标口承担，不做 1:1 硬分流 |
| 收容鬼 | 杂质改由采集鬼回收再送处理鬼，不设专用容器鬼 |
| 细嚼鬼 | 采集职能合并进采集鬼（DFS 搜索区） |
| 供品口（作为鬼） | v10 中贡品口与仓库口改为关卡设施，不是鬼 |
| 判官鬼 / 感应鬼 | v10 未启用；如需感知能力走「长期规划」 |

**v9 特有作废项**：v9 的「单能量累计产出计分」与 v10 的「贡品交付计分」正面冲突，以 v10 为准（见 `GameDesign.md` §16 C14）。
