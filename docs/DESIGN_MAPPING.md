# 设计对照：`GameDesign.md`（v15.2，§17 玩家视角，§18 机械联动）→ 本切片

> 这份文档回答两个问题：**设计里的哪些东西真的落地了**，以及**没落地的部分当时是怎么判断的**。
> 标注：✅ 已实现 · ◐ 部分实现 · ○ 不在本版范围 · ✕ 与设计不同（附理由）

---

## 1. 主干：v14.12 的关内循环

设计 §7.11.4.5 把「一关里玩家到底在干什么」定成：

```
补鬼能 → 调场 → 读场 → 决策
外敌从 360° 涌入 → 径直走向中央 → 被脉冲打中 → 死
清空 / 漏 10 只 → 回溯
```

本切片实现的就是这条主干，一步不少：

| 设计动作 | 本切片 |
|---|---|
| 补鬼能（换晶 / 搬晶） | 点鬼晶拿起 → 点机关插入；点机关取回 |
| 调场（挪鬼 / 挪机关 / 挪晶） | 建造 / 拆除（全额退款）/ 旋转朝向；暂停中同样可做 |
| 读场（热力图 / 振幅 / 两条线） | 每格热力图 + 共振指数 + 伤害线 / 清场线 |
| 决策（稳扎稳打 vs 搏一拱全爆） | 加鬼可能相消变冷；越线即抹杀 |
| 外敌 360° 涌入 | 波次表按 `center_deg / arc_deg` 刷怪 |
| 漏 10 只判负 | `max_breaches = 10` |
| 回溯到上一波 | 波次边界快照 + 面板确认后回滚 |

## 4. 有意偏离设计的地方（附理由）

1. **不用 Jolt 刚体做鬼**（§3 / 律二）
   设计要「物理承重」，不是「必须用刚体」。这里用单自由度倒立摆 + 几何接触保留力 / 力矩 / 阈值，
   换来确定性、可测试、可调参。详见 `docs/ARCHITECTURE.md` §8。
2. **伤害线 / 清场线的数值**
   设计没给数值。本切片取 `damage_line = 0.25`、`clear_line = 1.45`，
   是为了让「单只鬼能守住一条路、两只同相才能越线清场」成立；全部在 `Data/game.json` 可调。
3. **鬼晶容量 5、每次脉冲 +2**
   设计 v14.9 写「1 单位 = 一次脉冲的输出」，但同时要求闭环能自己转起来。
   1:1 会导致「每 2 秒必须换一次晶」的苦役；改成 5 容量 +2 补给后，
   节奏变成「约 10 秒换一次」，且仍然必须至少两颗轮换。
4. **4 向朝向而不是 8 向**
   网格是方形、机关的作用是「顶到脚 / 推到身」，4 向已经足以表达全部判定；
   8 向会让摆位变成像素对齐题，收益很低。
5. **失败后等待玩家点「回溯」**
   设计说「立刻回溯」。这里先冻结并展示战报，玩家确认后再回滚：
   同一结果，但玩家能看懂「是哪一只漏了、为什么」。
6. **没有鬼灯**
   §10 的灯是 v13 口径的教学载体；v14.12 的中央保护区已经承担了「必须持续供能」的教学职能。
   两者同时存在会让第一关有两个失败条件。
7. **相位对齐全场节拍**
   鬼立正时，相位不是从 0 开始，而是对齐到全场时钟（`fmod(now, period)`）。
   于是同周期的鬼天然同相，玩家不需要去凑「同时触发」的几帧——
   干涉只由**位置差**决定，可以靠摆位推演。设计里「时机」那条路被收掉了，
   换来的是一张稳定、可读、可以慢慢调的热力图。
8. **新增「甲魅」这一条敌人属性**
   设计里的魅只有「血量 / 速度 / 径直走」。这里加了 `armor`（普通脉冲减伤），
   因为它把「磨血」和「清场」变成两种真实解法：甲魅逼玩家把场摆成清场线，
   而清场线又要求两只同频鬼摆得够近。它没有引入第二套伤害系统，
   只是给既有的两条线加了一个「护甲」维度。
9. **自动化先做「搬运手」而不是「运输鬼」**
   设计 §7.8.1 想要的是物理接力链（鬼挨着传力、会掉件）。那需要一套新的
   力传递与碰撞规则，风险远大于收益。这里先做定点自动换晶：
   它解决的是「每 10 秒手动点一次」的重复劳动，同时用 `drain` 保留能量代价。
   手搬仍然更省，符合「自动化是高分路线、不是通关门槛」的设计意图。
10. **最后一波加了「魅王」**
   设计里没有 boss，但 v14.12 要求「每一关的高潮是一拱全爆」。一个走得慢、
   护甲极高的单体，能把玩家前面学的摆位 / 干涉 / 清场线全部压到同一刻：
   它漏过去直接判负，而清场线是唯一干脆的解法。它仍然是「被脉冲伤到的魅」，
   没有引入第二套战斗规则。
11. **用「两夜」的分段关卡代替无限连续世界**
   设计 v14.4 要的是一个永不结束的连续世界。本切片改成两夜、每夜四波：
   这样有明确的收尾、能验证数值、内容成本可控。世界仍然「连续」——
   同一夜的波次不间断推进，回溯只回到上一波；只是夜与夜之间有一块结算面板。
12. **机器共振（同拍大波段）**
   设计有清场线，但没有“整机同拍爆发”。这里把同一 tick 里多只同频鬼的脉冲振幅相加，
   越阈值就打出一次范围伤害 + 给地上晶充能的共振。相位改为按绝对时钟每 tick 重算，
   后立正的鬼也会落在同一拍上。它没有引入第二套战斗规则，只是让“机器变复杂”有直接回报。

### 与设计有出入的地方（v15）

1. **「传送带」是新加的一层，不是 v14.7 说的「机关就是传送带那一层」**
   v14.7 把「鬼能机关」比作传送带；实现时拆成两件更清楚的事：
   机关 = 把电变成力 / 改参数；传送带 = 只搬东西。两者共享「鬼晶是容器」这一条。
2. **装卸臂按「朝向」工作，不是全向**
   全向会让「去程 / 回程」退化成一只臂全包；朝向让物流成为一道 4 向摆放题。
3. **越界压力用「每处 +0.5 只/组」而不是面积占比**
   面积占比在 23×23 上太钝；每处计数让玩家每多摆一件都能立刻看到代价。
4. **越界造物被啃掉不退钱**
   设计说「不消失但持续引怪」；实现成「会被啃掉」更符合「集火」，也让扩张有真实损失。
   为了不让人一夜回到解放前，扩地会把仍活着的越界造物收编。
5. **锚鬼的「双支撑」不限机关类型**
   长撬 + 顶足是最省的做法；两根撬杆也可以。没有写死组合表。

## 8. v15.2 落地对照（§18）

| 玩家反馈 | 本切片 | 状态 |
|---|---|---|
| 「一圈都是推动，触发太单一」 | 六种触发：倾角 / 多支撑 / 脉冲接力 / **倾倒（锤鬼）** / **承重（撑鬼）** / **速度阈值（摆锤鬼）** | ✅ |
| 「鬼和鬼之间没有物理联动」 | 倒下的鬼砸进它倒向的那一格：砸脚帮它立正、砸身把它推倒；冲量下一 tick 结算，可连锁 | ✅ |
| 「鬼可以撑鬼」 | 撑鬼站着时撑住倒向它的邻鬼：算一个支撑、持续压脚、承重时发脉冲；超载会倒 | ✅ |
| 「锤鬼 → 摆锤」 | 锤鬼被推倒 → 砸摆锤 → 摆锤速度过阈值 → 一串脉冲；`--dev-link` 实测 `strikes=2, pend_pulses=2` | ✅ |
| 「机械美」 | 锤鬼立杆+重锤、撑鬼 A 撑架+承重垫、摆锤转轴+长臂+重锤；支撑连杆、砸击火花 | ✅ |
| 「取鬼晶太怪」 | 按住晶拖到机关松手插入；右键机关取晶；世界里半透明落点预览（绿/红） | ✅ |

### 与设计有出入 / 取舍

1. **锤鬼是「一次推倒 = 一次砸」**：回弹 5 rad/s 让它能反复锤，冷却 1.2 s；不能无限连砸。
2. **撑鬼的支撑是几何关系**：邻鬼的 `facing` 指向撑鬼才算撑住，不是任意相邻。
3. **摆锤鬼不能自己起振**：必须挨一下（锤鬼/倒下的鬼）；这是有意的，避免它变成「永动机」。
4. **普通鬼默认 `strike_torque=1.0`**：倒下会轻推邻鬼；数据可设 0 关掉。旧关卡的行为变化已在测试里锁住。
