## 1. 目标（做什么）

### G1 数值曲线完善（最高优先级）

从**玩家视角**出发，把当前的数值做成一条**优秀**的难度/收益曲线。要求：

- **你自己算**。不要拍脑袋改常数。至少建立一套可复算的量化模型，写进 `docs/`（例如 `docs/数值模型.md`），包含：
  - 每关的**期望通关时长**、**期望失败次数**、**单位时间产出**（鬼能/资源）；
  - 难度曲线的形状定义（前期教学陡度 → 中期变化 → 后期挑战），以及每个拐点的**理由**；
  - 至少 3 个关键指标的数值表，并说明改动前/改动后的对比。
- 曲线必须满足：单调不失控（有上限、有天花板）、前 3 关不卡死（首次接触不至于劝退）、后期有挑战但不靠堆数值。
- 依据：`Data/` 下的现有配置（`game.json`、`modifiers.json`、`ghosts/`、`levels/`、`crystals/`、`swappers/`、`mechanisms/`）与 `GameDesign.md`。
- 产出：改后的数据文件 + `docs/数值模型.md`（含公式与表格）+ 一段说明「为什么这样切分曲线」。

### G2 鬼可以拆除（当前不能拆是错的）

- 现在玩家**无法拆除已放置的鬼**，这是明确的设计错误。补齐拆除能力：
  - 交互方式与既有放置流程自洽（选中 + 确认，或右键/快捷键——你定，但要说清理由）；
  - 拆除有**明确代价或限制**（例如返还比例、冷却、操作耗时），避免「放错就白放」这种无脑最优解；
  - 拆除与鬼能结算的一致性必须正确，不能凭空产生或吞掉鬼能。
- 验收：放置 → 拆除 → 鬼能数值与预期一致（写一个可跑的断言/测试）。

### G3 键位修正：W 与 S 反了

- `W` 应为向上（远离屏幕下方），`S` 应为向下。当前映射相反，修正。
- 连带检查：方向键、相机移动、放置/拆除相关的其他输入是否也存在同类反向错误。全部对齐到「屏幕方向直觉」。

### G4 主角视角：平视全局机关 + 随意移动

- 主角需要一个能**平视看到所有机关**的视角（当前视角看不到全貌，玩家无法规划）。
- 在这个视角下主角必须能**随意移动**（自由走位，不被机关/地图边界卡死或别扭地限制）。
- 注意与 G3 的方向一致性：视角换到平视后，W/S/方向键仍必须是屏幕直觉方向。
- 不接受「只能滚动镜头、人不能走」或「人只能在极小范围内挪动」这类退化实现。

### G5 一进游戏的 UI 重新设计

- **进入游戏时的 UI 需要整体设计过**，不是现在的默认布局。请参考旧项目 `D:\GhostFactory\src` 里的 UI 资源与实现（`src/Code/UI/` 下的 `BackgroundLayer`、`UIFeedback`、`ArtPlaceholder` 等，以及 `src/Data`、`src/CopyWriting` 的文案风格）来借鉴视觉与信息层次。
- 设计要落地为真实场景/脚本改动，不是只写一份设计文档就算完。

### G6 鬼能图标的两处 UI 缺陷

- **G6a 放下鬼后图标还在**：主角放下鬼之后，鬼能图标仍然显示/残留。修正为放置成功后图标正确更新（资源变化要反映到图标上，不能留旧值）。
- **G6b UI 与鬼能图标打架**：现在的 UI 与鬼能图标重叠/互相遮挡。重新布局，保证不重叠、不压字、信息层级清晰。
